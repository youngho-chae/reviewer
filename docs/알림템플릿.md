# CATCHPASS 알림 템플릿 정본 (v1.1 · 2026-08-30)

시스템이 **자동 발송**하는 인앱 알림함 알림의 전체 카탈로그 — 카피 원문·발생 조건·변수·이동 링크·코드 정본.
**이 문서가 알림 카피의 정본이다** — 코드의 알림 문구를 바꾸면 이 문서를 함께 갱신한다(카피 원문주의).
기능정의서 §6.2(알림 매트릭스)는 이 문서를 참조한다.

## 0. 공통 규칙

- **채널**: 모든 자동 알림 = **인앱 알림함**(`db.notifications` — 체험자 `/r/notifications` · 사장님 `/o/notifications`, 벨 레드닷 소비). **웹푸시(기기 OS 알림)는 현재 어드민 수동 공지(§4)에만 연결** — 자동 알림의 푸시 확장은 `sendWebPushTo`(src/lib/push.ts) 재사용으로 후속 과제.
- **발송 시점 2종**: ①**이벤트 즉시** — 해당 API 처리 성공 직후 생성 ②**스윕(lazy)** — `sweepPassLifecycle`(pass-lifecycle.ts)·등급 재평가 스윕이 화면 접근 시점에 기한 경과분을 일괄 처리(별도 크론 없음 — 시각 명시 알림도 실제 생성은 다음 스윕 시점). 리마인드류는 패스별 플래그(`ownerRemindNotified` 등)로 **1회만** 발송.
- **익명 원칙**: 사장님 알림에 체험자 실명·닉네임·등급·익명 ID(#last4) 비노출 — 구분은 체험권 번호 `{체험권번호}`(`passRefNo` = "NO-" + 패스 ID 끝 6자 대문자). 예외: 스윕 리마인드 O-4의 "익명 #last4"(2026-07-31 개정 이전 표기 잔존 — §6 관찰 사항).
- **변수 표기**: `{매장명}` = Store.name(못 찾으면 "매장") · `{예약일시}` = `fmtReservationLabel` — **"8월 21일 (목) 오후 2시"** 12시간제 · `{시간}` = `fmtTime12` — "오후 2시"/"오후 2시 30분" · 금액 = 천 단위 쉼표+"원"(₩ 접두 금지) · 포인트 = 쉼표+"P".
- 알림 레코드: `{ id, userId, role: "reviewer"|"owner", title, body, createdAt, read:false, link? }` — link는 내부 경로만.
- **링크 원칙 (2026-08-30)**: link = **도달 시점에 존재가 보장되는 화면**만. 종착 상태 알림(만료·취소·기한 초과·검수 통과)은 **리스트**(`/r/passes` — 취소·만료 카드, `/r/passes?tab=review` — 기한 초과·검수 칩)로, 행동이 필요한 알림(리마인드·확정·제안·반려·사용 처리)은 **상세**(`/r/passes/{id}`)로 보낸다. 리마인드를 기한 경과 후 클릭하는 경우는 상세의 "만료/마감 지남" 렌더가 안전망.

## 5. 알림을 발송하지 않는 이벤트 (의도된 무발송)

- **체험자 본인 행위**: 발급(참여)·취소·리뷰 제출·예약 변경 — 화면 전환이 피드백(사장님 쪽만 O-1~O-3 발송). ※구 시드 데모의 체험자 "체험권 발급" 알림은 데모 데이터 전용 — 실 API 미발송.
- **사장님 본인 행위**: 사용 처리·발송 처리·예약 확정/제안/거절/취소·본인 캠페인 종료 — 상대(체험자) 쪽만 발송.
- **배송 지연 3일 경과**: 양측 화면 표시 전용 안내(상태 전이·알림 없음 — 리뷰 기한이 발송 후 롤링이라 불이익 없음).
- ~~반려 방치(7일 미재제출) 무알림~~ → **2026-08-30 개정: R-25(마감 24h 전)·R-26(기한 초과) 신설.** 재평가 반영은 그대로 분모만(무감점)이며 알림에도 감점 문구 없음. /r/grade 행동 가이드 카드 노출 유지.
- **등급 유지**: 월간 재평가 결과 등급 무변동이면 무발송.
