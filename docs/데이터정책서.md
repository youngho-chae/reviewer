## 1. 데이터 모델 (`src/lib/types.ts`)

### 1.1 Reviewer (체험자)
- `id`, `email`, `passwordHash`(bcrypt), `nickname`
- `sns: { kind: SnsKind, url, influence }[]` — SnsKind = `naver_blog | instagram | tiktok` (유튜브 없음)
- `grade: "S"|"A"|"B"|"C"|"N"` — 종합 등급 = 연동 채널 중 최상위
- `channelGrades?: Partial<Record<SnsKind, Grade>>` — 채널별 독립 등급
- `completedReviews`, `qualityScore`(0~100 — **deprecated**: 2026-07-08 재평가 설계에서 리뷰 품질 요소가 제외되어 미사용 확정, 제거하지 않고 유지만), `noShowCount`(만료·리뷰 기한(7일) 미제출 시 스윕이 자동 +1)
- `createdAt`, `termsAgreedAt?`(약관·개인정보 동의 시각)
- `inviteStats?: { sent, clicked, accepted, boxGrade }`
- **등급 월간 재평가 (2026-07-08)**: `gradeHistory?: GradeHistoryEntry[]` — `{month("YYYY-MM" KST), channel?(미지정=종합 요약), from, to, breakdown{I,F,W,P,GS}, neutralized?, skipped?, sCandidate?, winWinQualified?, at}` · `lastRegradeAt?` · `winWinBadge?: {since, lastQualifiedMonth}`(상생 리뷰어 — 유예 1개월, 2개월 연속 미달 시 회수)

### 1.2 Owner (사장님)
- `id`, `email`, `passwordHash`, `storeName`, `category`, `area`
- `plan: "Free"|"Basic"|"Standard"|"Premium"` (가입 기본값 Free)
- `createdAt`, `termsAgreedAt?`, `inviteStats?`
- **사업자 인증 (2026-07-08, 확정 정책 9)**: `bizNumber?`(10자리, 형식 검증만 — 진위는 운영팀 수기 확인) · `bizStatus?: "pending"|"verified"`(undefined = 제도 도입 전 계정 → verified 간주) · `bizVerifiedAt?`. pending이면 사장님 화면이 인증 대기 화면으로 대체된다.

### 1.3 AdminUser (운영팀)
- `id`, `email`, `passwordHash`, `role: "admin"`

### 1.4 Store (매장)
- `id`, `ownerId`, `name`, `category`, `area`, `coverEmoji`, `rating`, `reviewCount`, `hours`, `lat`, `lng`, `address`, `naverPlaceId`

### 1.5 Campaign (캠페인)
- `id`, `storeId`, `kind: "visit"|"press"`, `title`(**사장님 내부 관리용 캠페인명** — 선택 입력·≤40자, 미입력 시 매장명 자동. 체험자 화면은 항상 매장명 중심 노출 — 확정 정책 7), `startAt`, `endAt`, `supportAmount`(= S등급 100% 기준치)
- `quota: {S,A,B,C}`, `used: {S,A,B,C}` — **[P1] 참여 자격이 아닌 배분·집계용 버킷.** 발급 시 자기 등급 버킷 우선 차감(N은 C부터), 소진 시 잔여 버킷 사용. 총 잔여 0일 때만 마감.
- `requiredChannels: SnsKind[]`, `requiredMenus: {name, price?}[]`, `description`(≤500자), `highlightKeywords[]`(≤5·각 ≤20자)
- `useCode: string` — **숫자 4자리 사용처리 코드**
- press 전용: `pressKeywords[]`, `pressMaterials[]`, `pressMinChars`(레거시 — 제출 검증 미사용)

### 1.6 Pass (체험권) — 7-상태
- `id`, `code`(8자), `reviewerId`, `campaignId`, `storeId`, `ownerId`, `reviewerGrade`
- `consumedSlot?`("S"|"A"|"B"|"C") — 발급 시 **실제 차감한** 버킷(자기 등급과 다를 수 있음 — P1), 만료·취소 시 복구 근거
- `issuedAt`, `expiresAt`(**발급 후 72h** — 연장·복구 불가, 기자단은 캠페인 종료 시각), `usedAt?`, `cancelledAt?`(취소 후 동일 캠페인 12h 재신청 제한의 기준 시각)
- `paidAmount?`, `supportApplied?`, `supportBoostPct?`, `boostRewardId?`
- `reviewSubmittedAt?`, `reviewUrl?`, `reviewChannel?`, `reviewStatus?`, `reviewSelfCheck?: Record<string, boolean>`(채널별 가변 키)
- `adNoticeConfirmed?` — 광고 표기 확인 서버 보존(분쟁 근거)
- `keepAgreed?` — **게시 유지(90일) 동의** 서버 보존(2026-07-10). 자가 점검과 분리된 별도 필수 동의 — 미동의 시 리뷰 제출 400
- `rejectReason?`, `rejectedAt?`, `resubmitCount?`
- `completedAt?` — 운영팀 검수 승인 시각(2026-07-08). **월간 재평가의 완료·상생 집계 귀속 기준**(구버전 폴백: `reviewSubmittedAt ?? usedAt`)
- `overdueHandled?`, `expiringSoonNotified?`, `reviewDueSoonNotified?`(리뷰 마감 24h 전 알림 — 2026-07-10) — 라이프사이클 스윕 멱등 플래그
- `useCodeFailCount?`, `useCodeLockUntil?` — 4자리 사용 코드 오입력 가드(2026-07-10): 연속 5회 실패 → 10분 잠금. 실패 카운트도 영속(새로고침 우회 방지). **인증 실패로 status는 변경되지 않음**
- `status: "active"|"used"|"review_submitted"|"completed"|"expired"|"cancelled"|"rejected"`
- **파생 표시 상태(저장하지 않음, 2026-07-10)**: `src/lib/pass-display.ts` `passDisplayStatus()` — used+기한 초과 → `overdue`("제출 기한 초과"), rejected+재제출 기한/횟수 소진 → `resubmit_expired`("재제출 기한 초과"). 시간 경과만으로 결정되는 표시 계층 개념이므로 PassStatus를 확장하지 않고 렌더 시점 계산한다.

### 1.7 Interest (관심 목록 — 2026-07-07 회의)
- `reviewerId`, `campaignId`, `createdAt` — **캠페인 단위** 저장(매장 단위 아님).
- 캠페인이 종료(`closed`)돼도 레코드는 유지 — 목록에서 "마감된 체험"으로 표기하고 상세 진입은 허용하되 신청은 차단.
  진행 가능/마감 상태는 **렌더 시점에 `campaignExposure()`로 계산**한다(소진됐다 살아나는 별도 노출 상태를 저장하지 않음).
- 토글 API: `POST /api/interests` `{campaignId}` → `{saved}`.

### 1.8 NotificationItem / Reward / Invite / ViralCounter
- **NotificationItem**: `id`, `userId`, `role`("reviewer"|"owner"), `title`, `body`, `createdAt`, `read`, `link`
- **Reward**: `kind: support_bonus_pct | membership_discount | quota_bonus`, `value`, `source`(referrer_box|referee_welcome), `ownerUserId`, `issuedAt`, `expiresAt`(box 30일·welcome 14일), `usedAt?`, `meta?.matrix`
- **Invite**: `token`(8자, §5 charset), `referrerId`, `referrerKind`, `targetKind`, `status`, `createdAt`, `expiresAt`(14일), `consumedBy?`
- **ViralCounter**: `todayBoxCount`, `liveStream: { nickname, rewardText, ts, matrix }[]` (실 이벤트만, 조작 수치 없음)

### 1.9 DBShape (영속 컬렉션)
`reviewers / owners / admins / stores / campaigns / passes / notifications / invites / rewards / viralCounter / interests / seeded / seedVersion / naverDataFetched / lastRegradeMonth`
- `lastRegradeMonth?: "YYYY-MM"` — 등급 월간 재평가가 완료된 마지막 평가 대상 월(KST). 중복 실행 방지 메타(2차 방어는 reviewer별 `gradeHistory` month 중복 검사).

### 1.10 월간 재평가 파생 집계 원칙 (2026-07-08)
별도 이벤트 로그를 두지 않는다 — 재평가 시 `db.passes`의 기존 타임스탬프에서 파생 계산한다.

| 이벤트 | 월 귀속 기준 | 근거 필드 |
|---|---|---|
| 완료 | 검수 승인 시점 | `completedAt` (폴백 `reviewSubmittedAt ?? usedAt`) |
| 노쇼 만료 | 만료 시점 | `expiresAt` (status=expired) |
| 리뷰 기한 초과 | 기한 도래 시점 | `usedAt + 7d` (`overdueHandled=true`) |
| 반려 종착 | 최종 반려 시점 | `rejectedAt` + `resubmitCount≥1` |
| 상생(W) 집계 | 완료 건과 동일 | `paidAmount`·`supportApplied` 둘 다 있는 방문형 완료 건만 |

기한 초과 후 뒤늦게 완료된 패스는 초과 월 패널티 + 완료 월 크레딧으로 **각각 집계**된다.

## 2. 영속성 정책 (3-tier)

1. **모듈 전역 메모리** — 프로세스 수명. 개발·단일 인스턴스.
2. **`/tmp/catchpass-db.json`** — 파일 스냅샷. 서버리스에서는 인스턴스 재활용 시에만 유지(휘발 가능).
3. **Vercel KV (Upstash Redis REST)** — `KV_REST_API_URL`/`KV_REST_API_TOKEN` 설정 시 활성. **운영 배포 필수.**

- DB 로드(`getDB`/`getDBAsync`) 시마다 **라이프사이클 스윕**(`pass-lifecycle.ts`) 실행 — 변경 발생 시 KV/디스크 즉시 영속화.
- KV 미설정 시 서버리스 다중 인스턴스 간 발급 패스 불일치 위험(쿠키 stopgap 한정) → 운영에서 KV 필수(운영정책서 출시 체크리스트).

  - 실데이터 모드 기준 버전과 **스토리보드 모드 버전(1000+)을 분리** — 스토리보드는 시드 내용(스키마 라벨)이 달라 별도 버전. 현재 스토리보드 배포 버전 **1015**(2026-07-08: 등급 월간 재평가 — 직전 KST 월 활동 시드 + `completedAt` · v14=관심 목록 · v11=72h 유효기간).

## 4. 스토리보드(디자인) 모드 데이터 정책

> 목적: 디자인 파트가 "어떤 위치에 **어떤 종류의 데이터**가 들어가는지"를 실 목데이터 없이 확인.

- `src/lib/storyboard.ts`의 **`STORYBOARD` 플래그**로 토글. `true`면 모든 표시용 데이터를 한글 **스키마 라벨**로 치환:
  - 문자열(매장명/카테고리/지역/영업시간/주소/캠페인명·설명/메뉴명/닉네임/키워드/자료명)은 **시드 단계**에서 라벨 치환(`SB` 사전).
  - 숫자·복합 표현(지원금액/평점/리뷰수/잔여수량/거리/정산금액/가격/개수/날짜/매트릭스/토큰 등)은 **화면 단계**에서 `SBUI` 사전으로 치환.
  - **표기 형식 규칙(2026-07-07)**: `SBUI` 값은 라벨명이 아니라 **형식 예시(마스크)**로 노출한다 —
    금액 `000,000원` · 건수 `00건` · 수량 `00개` · 장수 `00장` · 인원 `00명` · 날짜 `0000.00.00` ·
    마감일 `00월 00일 까지` · 거리 기본 마스크 `00m`(실데이터 `00m`/`0.0km`/`00km`, 현 위치 기준) · 평점 `0.0` · 초대 코드 `ABC12345`.
    범주값(상태/채널/등급/유형)은 값 종류가 유한하므로 라벨명을 유지한다. **실데이터 렌더도 동일 형식**(원 접미·건/개/명 단위, ₩ 접두 금지)을 따른다.
  - 썸네일은 전부 `storyboard-thumb.svg` 1종 placeholder. GPS(reverse-geocode)는 스토리보드에서 비활성(지역="지역" 라벨 유지).
- 실데이터 원복: `STORYBOARD=false`로 전환 후 재시드(SEED_VERSION 정책에 따라). 실데이터 백업은 `backup/real-mockdata` 브랜치.
- **개인정보·진실성과 무관** — 스토리보드 라벨은 UI 자리표시일 뿐, 실 사용자 데이터를 다루지 않는다.

## 5. 토큰 · 코드 정책

| 종류 | 형식 | 규칙 |
|---|---|---|
| **초대 토큰**(`Invite.token`) | **8자 · 31자 charset(영대문자+숫자, 혼동 문자 `0 O 1 I L` 제외)** | TTL 14일 · 1회용(`consumedBy` 기록 시 재사용 차단) · 셀프 추천 차단 · 매트릭스 일관성 검증 |
| **사용처리 코드**(`Campaign.useCode`) | **숫자 4자리**(`/^\d{4}$/`) | 동일 사장님 진행 중 캠페인 간 중복 차단 · **체험자 화면 미노출**(사장님만 인지) · 오입력 가드 **연속 5회 실패 → 해당 체험권 10분 잠금**(`useCodeFailCount`/`useCodeLockUntil` 영속, 2026-07-10) · **시드는 QA 기준 "1234" 통일**(§3) |
| **Pass 고유 코드**(`Pass.code`) | 8자 영숫자 | QR 인코딩용, 스캔 시 단건 무충돌 조회 |

> 정정: 초대 토큰을 "base62"로 기재하던 문서·주석은 실제 구현(31자 대문자 charset, `TOKEN_ALPHABET`)에 맞춰 정정함. 데모 고정 토큰(예시 라벨)은 가독성 위해 별도로 지정될 수 있으며 생성 charset 규칙과 무관하다.
