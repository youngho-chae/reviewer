작성 2026-07-16 · `dev` 브랜치. 조사 방법: 웹 검색(사이트 직접 접근은 네트워크 정책 차단 — 검색 스니펫·이용 후기·스토어 설명 기반).
선행 벤치마크 `docs/벤치마크-레뷰.md`(배송형·포인트 도입)의 후속 — 이번 목적은 **예약형·배송형 프로세스의 구체화**.

## 1. 리뷰노트 조사 요약

| 영역 | 리뷰노트 방식 |
| --- | --- |
| 캠페인 유형 | 방문형 / 배송형 / 정보형(기자단) 대분류 + 포장형·구매형 파생. 유형별 검색 필터 |
| 캠페인 일정 | **신청기간 → 리뷰어 발표(선정) → 체험기간 → 리뷰 마감** 4단계 고정 일정. 상세에 제공 내역·장소·가능 요일 표기 |
| 방문형 진행 | 선정 → 카카오톡 알림 → **안내에 따라 방문 일정 예약** → 방문 체험 → 리뷰 URL 등록. 1일 전 예약 가능한 캠페인도 존재 |
| 노쇼·기한 | 선정 후 취소·기한 미이행 → **패널티 누적, 추후 선정 불이익**. 미이행 시 체험 금액 배상 조항 |
| 배송형 진행 | 선정 → 배송지 → 발송 → 수령 체험 → 리뷰 마감 내 등록. **발송 지연이 리뷰어 최대 불만** (마감은 다가오는데 상품 미도착) |
| 포인트 | 체험 완료 포인트 적립 → 현금 출금 |

## 2. 구조 차이 — 그대로 이식 금지 항목

| 리뷰노트 | CATCHPASS | 판정 |
| --- | --- | --- |
| **선정 절차** (신청 → 발표) | 등급 기반 **즉시 발급** (선착순) — 서비스 차별점이자 P1(등급=혜택 크기)의 기반. 선정 심사는 "신청한마디·채널 규모"가 사실상 자격이 되어 P1 철학과 충돌 | **보류** — 즉시 발급 유지. 예약형도 "발급 후 일정 조율"로 변환 |
| 노쇼 → 선정 불이익 | 노쇼는 월간 등급 재평가 감점(성실 이행)으로만 — **참여/발급 분기 참조 금지(P1)** | 기존 정책 유지 |
| 구매형(실구매 후 지원) | 구매평·페이백은 P4 리스크 — 벤치마크-레뷰 §13 #18에서 이미 보류 | **보류 유지** |
| 리뷰 마감 = 캠페인 고정일 (배송 지연 시 리뷰어 불리) | 리뷰 기한 = **발송 후 7일 롤링** — 지연 리스크가 리뷰어에게 전가되지 않음 | 우리 방식 유지 + 발송 지연을 **표시·안내**로 보완 |

## 3. 적용 항목 (이번 구체화)

### 3.1 예약형 방문 (reservationRequired) — "예약형 라이트" → 실제 예약 플로우

리뷰노트의 "선정 후 일정 예약"을 즉시 발급 구조로 변환: **신청 시 희망 방문 일시 선택 → 사장님 예약 확인**.

- 신청(발급) 시 **희망 방문 일시 필수 선택** — 날짜(오늘~14일 이내·캠페인 종료일 한도) + 시간(30분 단위 슬롯). `Pass.reservation { date, time, status }`.
- **체험권 유효기간 = 예약일 당일 말(KST 23:59)** — 72h 고정 기한의 명시적 예외 (배송형이 캠페인 종료일까지인 것과 동일 원리). 미방문 시 기존 만료 스윕이 그대로 처리(슬롯 복구·노쇼 카운트).
- 사장님 홈에 **예약 확인 큐** — [예약 확인] 버튼으로 확정(`requested → confirmed`) + 체험자 알림. **거절 기능은 만들지 않는다** — 예약은 참여 승인이 아니라 일정 조율(P1: 참여를 막는 조건 3가지 외 금지). 일시가 곤란하면 매장이 연락해 조율하고 체험자가 예약을 변경한다.
- 체험자는 사용 전 **예약 변경** 가능(재확정 필요·유효기간 재계산). 예약 미확정이어도 QR 사용은 가능(사용 게이트 아님).
- 캠페인에 `reservationNote` (가능 요일·시간 안내 — 리뷰노트 상세의 "가능 요일" 대응).
- 노쇼 = 기존 만료(재평가 감점 종착)와 동일 — 리뷰노트식 배상·선정 불이익은 도입하지 않음.

### 3.2 배송형 구체화

- **상품 옵션** `Campaign.productOptions`(최대 5) — 신청 시 택1(`Pass.shipping.option`), 발송 큐에 표시. (리뷰노트 배송형의 옵션 선택 대응)
- **택배사 + 운송장 조회** — 발송 처리 시 택배사 선택(`Pass.courier`, 정본 `src/lib/couriers.ts`), 체험자 화면에 운송장·[배송 조회] 링크(택배사별 조회 URL).
- **발송 지연 표시** — 신청 후 3일 경과 미발송 시 체험자 화면 지연 안내 + 사장님 발송 큐 지연 강조. 상태 확장 없음(렌더 시점 계산 — pass-display 원칙). 리뷰 기한이 발송 후 7일 롤링이라 리뷰어 불이익이 없음을 함께 고지.

### 3.3 상세 화면 정보 구조

- 예약형: 배너를 실제 플로우 카피로 교체("신청 시 희망 방문 일시 선택 → 사장님 예약 확인") + `reservationNote` 노출 + 이용 방법 스텝 분기(일시 선택 → 예약 확인 → 방문·QR → 리뷰) + 유의사항에 예약 변경·노쇼 항목.
- 배송형: 옵션 존재 시 신청 시트에 옵션 선택. 유의사항에 발송 지연·리뷰 기한 롤링 명시.
