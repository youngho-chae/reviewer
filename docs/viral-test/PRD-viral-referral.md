## 1. 배경과 문제 정의

CATCHPASS 핵심 가치는 "선정 기다리는 체험단 말고, 등급으로 즉시 받는 체험권." 이미 활성 사용자(체험자·사장님)는 매장에서 QR을 발급/사용하는 **고관여 액션**을 자주 한다. 이 순간의 만족감(=즉시 차감되는 지원금, 등급 상승, 캠페인 노출)을 *공유 가능한 자산*으로 전환하지 않으면 — 곧 바이럴 동력 누수가 일어난다.

Toss의 그로스 팀이 송금/카드 추천 캠페인에서 입증한 다음 6개 원리를 CATCHPASS의 현재 액션 그래프에 매핑한다.

| Toss 바이럴 원리 | 핵심 가설 | CATCHPASS 매핑 (요약) |
|---|---|---|
| 즉각적 보상 (Instant Gratification) | 보상은 "행동 직후 ≤ 5초" 안에 체감되어야 한다 | 추천 링크 클릭 즉시 양측 보상 박스 오픈 — 가입 완료 전에 받는 사람도 먼저 미리보기 |
| 양면 인센티브 (Two-sided Reward) | 받는 쪽만 이득이면 신뢰 결여, 보내는 쪽만 이득이면 친구를 도구화 | 추천자 = "행운 박스 1회권", 피추천자 = "첫 캠페인 지원금 +50% 가산 쿠폰" |
| 마찰 최소화 (Frictionless Sharing) | 공유는 1~2 탭이어야 한다. 카피·이미지 미리 생성 | 패스 상세 / 캠페인 생성 완료 화면에 [친구에게 쏘기] FAB · Web Share API → 카톡/SMS/링크 복사 단일 시트 |
| 사회적 증거 + FOMO | "지금 이 순간 N명이 받고 있어요"의 실시간 카운터 | 박스 오픈 화면 상단에 `오늘 이 박스로 N명이 평균 ₩X,XXX를 받았어요` 라이브 카운터 (1초 주기 mock SSE) |
| 게이미피케이션 (Variable Reward) | 동일 보상 < 가변 보상 (도파민 변동성) | "행운 박스" — 슬롯 머신 애니메이션 + 3종 상자(일반/실버/골드) + 누적 진행도 바 (5명 초대 → 골드 박스 1회 보장) |
| 재방문 훅 (Hook Loop) | 트리거→행동→가변 보상→투자 사이클을 catchpass 핵심 액션에 묶는다 | 친구 가입 알림 = 트리거 / 박스 오픈 = 행동 / 가변 보상 = 보상 / 다음 친구 초대·캠페인 참여 = 투자 |

## 2. 페르소나 + 추천자 트라이앵글

3개의 행위자가 등장한다.

```
   추천자 (Referrer)            피추천자 (Referee)            매장 (Indirect Beneficiary)
   ─────────────────             ──────────────────            ───────────────────────
   기존 체험자 또는 사장님       신규 체험자/사장님 후보       추천 가입자가 발급한 패스로
   ▼                             ▼                             자연스럽게 모객 효과 확대
   [친구에게 쏘기 FAB] 누름        딥링크 진입 → 박스 오픈        ▼
   ▼                             ▼                             멤버십 업그레이드/캠페인 추가 발주
   양면 보상 카드 열림           즉시 보상 미리보기            (장기 LTV 상승)
   ▼                             ▼
   친구 가입/첫 액션 완료 시     가입 1탭 완료 + 첫 캠페인 지원금 +50% 쿠폰
   "행운 박스" 1회권 적립
```

추천 대상은 두 사이드 모두에 열려 있다 — **양방향 매트릭스 4가지**:

|  | → 체험자 초대 | → 사장님 초대 |
|---|---|---|
| **체험자 발신** | RR (체험자가 친구 체험자 추천) | RO (체험자가 단골 매장에 사장님 가입 추천) |
| **사장님 발신** | OR (사장님이 손님에게 가입 추천 — 매장 QR로 자동 발급) | OO (사장님이 동료 사장님 추천 — B2B 입소문) |

각 매트릭스마다 **보상 종류·금액·발화 채널**이 다르게 설계되어야 한다 (자세한 표 §6).

## 3. 핵심 사용자 흐름

### 3.1 추천자 흐름 (체험자 → 체험자, RR 케이스가 기본)

```
[/r/passes/[id]] 패스 사용 직후 (used → review_submitted 사이) ─ 트리거 지점
   │
   │  ▼ "지원금 ₩X,XXX 절약 완료!" 모달 1.5초
   ▼
[/r/passes/[id]] 모달 닫힘 → 본문 하단 카드 노출
   │  [🎁 친구에게 쏘기 — 친구도 ₩XX,XXX, 나도 행운 박스]
   ▼  1-tap
[/r/invite/new] 공유 시트 (Web Share API)
   │  · 자동 생성 카피: "{닉네임}님이 친구에게 ₩XX,XXX 지원금을 보냈어요"
   │  · 자동 생성 이미지(OG): 매장 사진 + 닉네임 + 지원금 (canvas 합성)
   │  · 채널: 카톡 / SMS / 인스타 DM / URL 복사
   ▼
[딥링크 발사: https://catchpass.app/i/<token>]
   │  세션 쿠키 cp_invite=<token>
   ▼
   (피추천자 흐름으로 이어짐 §3.2)
```

### 3.2 피추천자 흐름 (Referee)

```
[딥링크 진입 → /i/<token>]
   │  · 토큰 lookup → 추천자 닉네임 + 매장 컨텍스트 + 보상 미리보기
   │  · "{닉네임}님이 ₩XX,XXX 첫 캠페인 쿠폰을 보냈어요. 박스를 받으려면 30초 가입"
   ▼
[/r/signup?invite=<token>] 가입 폼
   │  · 일반 가입과 동일하지만 헤더에 [선물 도착 — 가입 후 자동 적용] 카드
   ▼  가입 완료 (회원생성 시점에 inviteToken 검증·소비)
[/r/welcome/box] 행운 박스 오픈 화면
   │  · 슬롯 머신 애니메이션 1.8초 → 결과 카드
   │  · 결과 = 첫 캠페인 지원금 +50% 가산 (확정) + 0~5,000원 보너스 캐시(가변)
   ▼
[/r/home] 정상 진입
   │  · 매장 카드에 "쿠폰 적용 시 ₩XX,XXX" 라벨 추가
   ▼
   (이후 행동은 기존 catchpass 흐름과 동일)
```

### 3.3 시너지 트리거 — 기존 catchpass 액션과 결합

5개 트리거 지점에서 추천 모듈이 자동으로 등장한다 (모두 어댑터 콜로 결합, 기존 컴포넌트 무수정):

| # | 기존 액션 (메인 PRD §) | 추천 모듈 노출 위치 | 발화 카피 |
|---|---|---|---|
| T1 | 패스 사용 직후(used → review_submitted, PRD §3.1) | `/r/passes/[id]` 하단 sticky 카드 | "오늘 ₩X 절약. 친구도 받게 해줄래요?" |
| T2 | 리뷰 제출 후 completed 도달 | `/r/notifications` 푸시 토스트 | "검수 통과! 행운 박스가 도착했어요" |
| T3 | 등급 상승(C→B→A) 알림 | `/r/grade` 상단 배너 | "등급이 올랐을 때 추천하면 박스 등급도 같이 올라가요" |
| T4 | 사장님 캠페인 생성 완료(POST /api/campaigns 200) | `/o/campaign/new` success screen | "이 캠페인을 친구 사장님에게 추천 — 양쪽 다 첫 달 멤버십 50% 할인" |
| T5 | 사장님 패스 스캔 완료(/o/scan after use) | 결과 화면 하단 | "이 손님에게 가입 안 했으면 가입하라고 권유 — 손님도 박스 받음" |

이 매핑은 PRD §4 시나리오 A·B·C·D·E의 **종료 지점**에 일관되게 붙는다.

## 4. 보상 설계 (Two-sided + Variable)

### 4.1 추천자 보상 — "행운 박스"

- **확정 보상**: 1회권 (체험자) / 멤버십 다음 결제 1만원 할인 쿠폰 (사장님)
- **가변 보상**: 박스 등급 = 누적 성공 초대 수 함수
  - 1~2명 성공 → 일반 박스 (₩1,000 ~ ₩3,000 보너스 캐시, 등급 점수 +2)
  - 3~4명 → 실버 박스 (₩3,000 ~ ₩8,000, 등급 점수 +5)
  - 5명+ → 골드 박스 (₩8,000 ~ ₩20,000, 등급 점수 +10, 시그니처 매장 1회 우선 노출권)
- **단순 누적 진행 바**: `[▰▰▰▱▱] 다음 박스까지 친구 2명`
- **꽝 없음 정책**: 최소 ₩1,000은 보장 — Toss 사례에서 입증된 신뢰 유지 핵심

### 4.2 피추천자 보상 — "환영 박스"

- **확정 보상**: 첫 캠페인 패스 발급 시 지원금 +50% 가산 (예: ₩50,000 → ₩75,000)
  - 사장님이 받을 경우 → 첫 달 멤버십 50% 할인 + 첫 캠페인 모집 한도 +5팀
- **가변 보상**: 0~5,000원 즉시 보너스 캐시 (가입 후 30일 내 사용)
- **유효기간**: 14일 (FOMO 강화)

### 4.3 양면 매트릭스별 보상 표

| 발신·수신 | 추천자 (행운 박스) | 피추천자 (환영 박스) | 의도 |
|---|---|---|---|
| RR (체험자→체험자) | 박스 등급(누적), 보너스 캐시 | 첫 캠페인 지원금 +50%, 보너스 캐시 | 코어 그로스 루프 |
| RO (체험자→사장님) | 골드 박스 즉시 + 시그니처 우선 노출권 2회 | 첫 달 멤버십 50% 할인 + 모집 한도 +5팀 | 단골 손님 → 매장 영업 |
| OR (사장님→체험자) | 캠페인 모집 한도 +3팀 (영구 적립, 최대 +20) | 해당 매장 첫 캠페인 지원금 +50% + 보너스 캐시 | 매장 QR 자체에 추천 코드 임베드 |
| OO (사장님→사장님) | 멤버십 다음 결제 1만원 할인 + 골드 박스 | 첫 달 멤버십 50% + 모집 한도 +5팀 | B2B 입소문 |

## 5. 마찰 최소화 — 공유 1탭 설계

### 5.1 공유 시트
1. 트리거 지점 sticky 카드의 [🎁 친구에게 쏘기] 단일 CTA
2. 탭 → Web Share API 호출 (가능한 경우) — 그 외 fallback 모달
3. 자동 채워지는 텍스트 + 자동 합성 OG 이미지 + 단축 URL
4. 카톡/문자/링크 복사 중 하나 선택

### 5.2 매장 QR 임베드 (OR/OO 케이스의 마찰을 0으로)
- 사장님 캠페인 생성 시, **매장 QR 자체에 추천 코드 자동 임베드**
- 손님이 매장 QR을 스캔해서 패스를 발급받는 순간 — 매장 추천 코드도 동시 적용
- 즉, 사장님이 "추천해주세요"라고 손님에게 말하지 않아도 → 매장 방문 자체가 추천 행위가 됨
- 추천자 = 매장(=사장님), 피추천자 = QR 스캔 후 가입한 신규 체험자

이게 우리만의 차별 포인트다 — Toss는 송금 채널을 가졌지만, CATCHPASS는 **오프라인 QR 채널**을 가졌다.

### 5.3 딥링크 토큰 형식
- `https://catchpass.app/i/<base62 8자>` — 8자 영숫자(헷갈리는 0/O/1/I/L 제외)
- 토큰 페이로드(서버 보관):
  ```ts
  interface InviteToken {
    id: string;              // 8자 base62
    referrerId: string;       // reviewer/owner id
    referrerKind: "reviewer" | "owner";
    targetKind: "reviewer" | "owner";  // matrix 결정
    storeId?: string;         // 매장 QR 임베드용
    createdAt: number;
    expiresAt: number;        // 14일
    consumedBy?: string;       // referee user id (1회용)
    consumedAt?: number;
  }
  ```

## 6. 사회적 증거 + FOMO

### 6.1 박스 오픈 화면 상단 라이브 카운터

```
┌──────────────────────────────────────┐
│  🎁 박스 도착 — {닉네임}님이 선물      │
│                                       │
│  오늘 이 박스로 ▮ 1,283명이 평균       │
│  ₩4,250을 받았어요                    │
│  (1초마다 +1~3명씩 카운트 업)         │
└──────────────────────────────────────┘
```
- 카운터는 mock SSE/setInterval로 매초 ±3 변동
- "방금 강남 박OO님이 ₩8,000 받음" 같은 한 줄 라이브 토스트도 동시 송출 (FOMO 자극)

### 6.2 잔여 시간 FOMO
- 환영 박스 미오픈 시 홈 헤더에 `박스가 D-{n}일 남았어요` 빨간 점 배지
- D-1 진입 시 푸시 알림 1회 발사 (mock)

## 7. 게이미피케이션 — Variable Reward 연출

### 7.1 박스 오픈 애니메이션 시퀀스
1. 박스 흔들리기 (0.0~0.6s) — 사용자 탭 진입 시 자동 시작
2. 슬롯 머신 휠 3개 회전 (0.6~1.8s) — 매장 카테고리 / 보상 종류 / 금액
3. 결과 잠금 → 카드 플립 (1.8~2.2s)
4. 컨페티 + 보상 카드 (2.2s~)
5. CTA 2개: [지금 사용 →] [친구에게도 쏘기 →]

이 시퀀스를 React + framer-motion(또는 CSS keyframes)으로 구현 — 전체 < 30 KB.

### 7.2 누적 진행도 바
- `[▰▰▰▱▱] 다음 박스까지 친구 2명`
- 각 매트릭스(RR/RO/OR/OO)는 독립 진행도

## 8. 데이터 모델 (어댑터 + mock 인메모리)

본 트랙은 기존 `DBShape`를 건드리지 않는다. 별도 `MockStore` 인스턴스에 다음을 저장:

```ts
interface ViralUser {

  role: "reviewer" | "owner";
  nickname: string;
  inviteStats: {
    sent: number;        // 발송 클릭 수

    cumulativeBoxReward: number;
  };

}

interface Invite {
  token: string;
```

## 10. OKR 검증 — 3개월 + 그 이후

### 10.1 출시 후 3개월 (주어진 OKR — Acquisition 단계)

| 항목 | 목표 | 도달 가정 |
|---|---|---|
| 신규 체험자 (organic + paid) | **20,000명** | 마케팅·SEO·SNS 콜라보로 일 222명 모객 |
| 신규 사장님 (organic + paid) | **10,000명** | 영업·매장 콜드콜·파트너십으로 일 111명 모객 |

이 단계는 본 추천 기능이 *추가 유입을 만드는 단계는 아님*. 다만 다음을 동시에 충족해야 다음 단계가 가능:

- 본 추천 기능을 **출시 1개월 차에 100% 출시**해, 2~3개월 차 누적 활성 사용자가 추천을 경험한 상태로 진입
- **추천 발신율(=신규 가입자 중 30일 내 1회 이상 초대 발송) ≥ 25%** — 이게 0이면 4개월 차 viral 2× 불가능

### 10.2 3개월 이후 — Viral 2배 OKR 검증 (수학적 시뮬레이션)

목표: 추가 체험자 **+20,000명**, 추가 사장님 **+10,000명** — **전부 referral 채널**.

**K-factor 계산**:
```
K = (active_inviter_ratio) × (invites_per_inviter) × (conversion_rate)
  = 0.30 × 3.5 × 0.40
  = 0.42
```
누적 viral 사용자 = `N_seed × K / (1 - K)` 가 정상 상태에서.
- N_seed = 20,000 (체험자) × 0.42 / 0.58 ≈ 14,483명 → **부족**.

**필요한 K 보정**:
2x viral 달성을 위해 cumulative ≥ 2 × seed 필요.
- `K / (1 - K) ≥ 2` → `K ≥ 0.667`

이건 도전적이지만 Toss가 송금 캠페인 일부에서 도달한 영역. CATCHPASS는 다음 레버로 이걸 가능하게 함:

1. **매장 QR 자동 임베드** (§5.2) — OR 매트릭스가 *수동 발신 0건으로도 작동*. 매장 일 평균 방문자 100명 × 추천 임베드 → 가입 전환율 5%만 잡혀도 매장당 일 5명, 1만 매장 × 30일 = 매월 1.5M 가입 잠재 — 실제 conversion×friction 보정 후 K 기여 0.25
2. **양방향 매트릭스 4종** — 단일 RR 추천이 아닌 RR+RO+OR+OO 합산이 K
3. **확정 보상 + 가변 보상 + 누적 진행도 게이미피케이션** — 발송 동기 강화 → 활성 발신율 0.30 → 0.45 가능
4. **소셜 증거 라이브 카운터** — 클릭→가입 전환율 0.40 → 0.55 가능 (사용자 인터뷰 기반 추정)

레버 적용 시:
```
K_with_levers = 0.45 × 3.5 × 0.55 + 0.25 (QR 임베드 보정)
              = 0.866 + 0.25
              = 1.116  (이론적 상한; 실측은 보수적으로 0.7~0.9 예상)
```

K=0.7 가정 시:
```
viral_total / seed = K / (1-K) = 0.7 / 0.3 = 2.33
viral cumulative = 20,000 × 2.33 ≈ 46,600명 → ✅ 목표(20,000) 초과 달성
```

K=0.5 (보수치) 가정 시:
```
viral_total / seed = 0.5 / 0.5 = 1.0
viral cumulative = 20,000 × 1.0 = 20,000명 → ✅ 목표 정확 달성
```

K=0.4 (실패 시나리오):
```
viral_total / seed = 0.667
viral cumulative = 13,333명 → ❌ 목표 미달 (66.7%)
```

**결론**: K ≥ 0.5 유지가 핵심. 본 설계에서 K=0.5는 **출시 후 1개월 차에 검증해야 하는 first gate**다. 미달이면 보상 금액·박스 가변폭·매트릭스 노출 빈도를 즉시 조정.

### 10.3 사장님 사이드 — 동일 모델

사장님은 행동 빈도가 낮아 RR 매트릭스에 의존 어려움. 대신:
- **OO 매트릭스** (B2B 입소문) → 한 사장님이 평균 1.2명 동료 사장님 추천, 수락률 35% → K_OO = 0.42
- **RO 매트릭스** (체험자→사장님) — 단골 손님이 매장에게 "여기 가입 추천" → 누적 효과
- 결과 K_owner ≈ 0.55 예상 → 10k seed × 1.22 = **12,200명** ≈ 목표 10k 충분히 달성

### 10.4 3개월 이후 AARRR 풀세트 OKR

본 트랙은 Acquisition·Referral에 집중하나, 출시 후 6개월 시점 풀세트 OKR을 함께 정의:

| 단계 | KPI | 목표 (6개월 누적) |
|---|---|---|
| **A**cquisition | 신규 가입 (organic + paid + referral) | 체험자 60k / 사장님 25k |
| **A**ctivation | D7 첫 패스 발급 / 첫 캠페인 생성 | 70% / 65% |
| **R**etention | D30 재방문 (앱 오픈 또는 패스 발급) | 45% / 55% |
| **R**eferral | 활성자 중 1회+ 초대 발송율 / K-factor | 35% / 0.55 |
| **R**evenue | 사장님 유료 전환 (Free → Basic 이상) / 월간 매출 | 28% / ₩ 280M |

이 표는 본 추천 기능이 단순 신규 유입뿐 아니라 **Retention(박스가 재방문 훅) · Revenue(사장님 멤버십 업그레이드 유도)**에도 기여한다는 의도를 반영한다.

## 11. 가드레일 — 어뷰징 / 윤리

- **자기 자신 추천 차단**: 토큰 referrerId === refereeId 거부 (회원가입 device fingerprint 일치도 차단)
- **링 방지**: 한 IP/디바이스에서 24h 내 3회 초과 가입 시 자동 보상 hold (운영팀 검수)

- **개인정보**: 추천자 정보는 닉네임만 노출 (이메일·SNS URL 비공개)

## 13. 자체 시나리오 검증 (PRD 자체 점검)

OKR 달성 가능성을 시나리오로 점검:

**시나리오 A — 정상 K=0.55 케이스**
- 3개월 후 활성 체험자 20k
- 30% 초대 발송 × 3.5건 × 40% 전환 = 신규 8,400명
- 이 신규가 다시 동일 K → 8,400 × 0.55 = 4,620 → 2,541 → ...
- 누적 (geometric series): 20k × (0.55/(1-0.55)) = **24,444명** → ✅ 2배 목표 24k 초과 달성

**시나리오 B — K=0.4 위기 케이스**
- 누적 referral = 20k × 0.667 = 13,333 → ❌ 미달
- **자동 대응**: §12 W5 게이트에서 발견 → 보상 +30% 적용 → K=0.5 회복
- 회복 가정 시 누적 = 20k → 목표 정확 달성

**시나리오 C — 매장 QR 임베드 본격화 케이스 (OR 매트릭스)**
- 1만 매장 × 일 50명 스캔 × 5% 신규 가입 = 일 25,000명 잠재
- 실제 보수적 conversion 1% 가정 → 일 5,000명
- 30일 = 150,000명 → 사장님 사이드 목표(10k) 압도적 초과, 체험자 사이드도 자력 달성

위 3개 시나리오 모두에서 ① K ≥ 0.5 유지와 ② 매장 QR 임베드 출시는 OKR의 *결정적 의존 변수*. 본 PRD는 두 변수 모두 출시 시점에 활성 상태로 시작하는 것을 전제로 한다.
