# 벤치마크 — 레뷰(REVU, revu.net) v1.0 (2026-07-12)

경쟁 체험단 플랫폼 레뷰를 조사하고, CATCHPASS에 적용할 항목과 보류할 항목을 정책 불변식(PRD §1.0)과 대조해 판정한 문서.

> **조사 방법·한계**: revu.net 본문은 개발 환경의 네트워크 정책상 직접 접근이 차단되어(게이트웨이 403),
> 공개 2차 자료(약관 인용·이용 가이드·뉴스·앱 정보)와 웹 검색으로 조사했다. 수치는 조사 시점 기준이며
> 레뷰 측 정책 변경으로 달라질 수 있다. 출처는 각 절 하단에 표기.

## 1. 레뷰 서비스 구조 조사 결과

### 1.1 캠페인 유형 (상품군)

| 유형 | 진행 방식 | 보상 형태 |
|---|---|---|
| **방문형(지역)** | 매장 방문 체험 후 리뷰. 예약 여부·운영시간 확인 후 신청. 물리 제약으로 경쟁률 낮음 | 서비스/식사 무상 제공 |
| **배송형(제품)** | 상품을 택배로 수령해 집에서 체험 후 리뷰. 전국 단위 지원이라 경쟁률 높음 | 제품 무상 제공 |
| **기자단** | 체험 없이 제공 자료(원고 소재)로 콘텐츠 작성 | 원고료 포인트 (건당 약 1,000~50,000원, 통상 10,000원) |
| **구매평(페이백)** | 자비로 선구매 → 구매확정·구매평 작성 → 제품비를 포인트로 페이백 | 포인트 페이백 |
| **포장(테이크아웃)** | 방문 수령 후 자택 체험 — 방문형과 배송형의 중간 | 제품 무상 제공 |
| **예약형** | 숙박·미용 등 선정 후 매장과 일정 예약을 확정하고 방문 | 서비스 무상 제공 |

- 채널: 네이버 블로그 · 인스타그램 · 유튜브 · 틱톡 · 클립(숏폼) 등. 활동 미디어 연동 시 맞춤 캠페인 추천.
- 캠페인 카드: 모집 인원 대비 신청자 수(경쟁률), 제공 내역, 신청 마감일 노출.

### 1.2 포인트 제도

- **적립**: 기자단 원고료·구매평 페이백 등 현금성 보상을 포인트로 지급. 1P = 1원.
- **출금**: 계좌 등록 후 인출 신청 → 약 4~6일 내 지급. 최소 출금 10,000P·1만 단위
  (케이뱅크 제휴 계좌는 5,000P부터·수수료 면제 — 2024-02 제휴).
- **세금(약관 명시)**: 환급 시 세금·제반 수수료를 환급 요청 금액에서 차감.
  - 원천징수 대상 **사업소득 세율 3.3%** (소득세 3% + 지방소득세 0.3%)
  - 원천징수 대상 **기타소득 세율 22.2%** (소득세 20% + 지방소득세 2% — 필요경비 공제 전 표기)
- **제한**: 블랙 페널티 상태에서는 포인트 출금 불가.

### 1.3 세금 처리 일반 규칙 (국세청 기준 — 우리 정책 설계의 근거)

- **사업소득(계속·반복 활동)**: 지급액의 3.3% 원천징수. 리뷰 활동을 계속·반복적으로 하는
  리뷰어에 대한 실무 표준. 연 환산 소득이 일정 규모면 종합소득세 신고 대상.
- **기타소득(일시·우발 활동)**: 필요경비 60% 인정 → 기타소득금액 = 지급액 × 40%.
  원천징수 = 기타소득금액 × 22% = **지급액의 8.8%**.
  **과세최저한**: 기타소득금액 건당 5만 원 이하(= 지급액 125,000원 이하)는 원천징수하지 않음.
- **소액부징수**: 원천징수세액이 1,000원 미만이면 징수하지 않음 (소득세법 §86).
- 실서비스 운영 시 원천징수이행상황신고·지급명세서 제출을 위해 **실명·주민등록번호 수집**이
  필요하다 (출금 신청 시점 수집이 최소 수집 원칙에 부합).

### 1.4 운영 정책

- **콘텐츠 유지 기간**: 캠페인 결과 발표일로부터 **180일(6개월)** (레뷰셀렉트는 등록일부터 180일).
- **페널티**: 콘텐츠 등록 지연·미션 불이행·공정위 문구 미표기 시 '주의' 페널티,
  **주의 5회 누적 → 블랙** (캠페인 신청 제한 · 포인트 출금 불가 · 커뮤니티 제한).
- **공정위 대가성 표기**: 스폰서 배너(대가성 명시) 미삽입 시 콘텐츠 등록 자체 불가.
- 부가 서비스: REVU LINK(링크-인-바이오 프로필), 레뷰 캐스팅(광고주-인플루언서 매칭) 등.

## 2. CATCHPASS 적용 판정 (정책 불변식 대조)

### 2.1 이번에 반영 (구현)

| # | 항목 | 반영 내용 | 불변식 대조 |
|---|---|---|---|
| 1 | **배송형 캠페인** | `CampaignKind`에 `delivery` 추가. 신청 시 배송지 입력 → 사장님 발송 처리(운송장) → 수령 체험 → 리뷰 7일. 지역 무관 전국 참여 | P1 충족: 참여 차단 조건은 종료/채널 미연동/슬롯 소진 3가지 그대로. P2는 방문형 전용 원칙이므로 배송형은 별도 정산 모델(§3.2) |
| 2 | **포인트 지급** | 배송형 캠페인의 선택 옵션 `pointReward`(체험 포인트). 리뷰 **검수 승인 시** 적립 — 실제 발생 이벤트만 (P4). 지급액 = pointReward × 등급 배율(P1: 등급은 혜택 크기) | P4·P5 충족(소비 경로 = 출금 구현) |
| 3 | **포인트 출금 + 세금 처리** | 1P=1원 · 최소 10,000P · 1,000P 단위 · 이체 수수료 500P. **사업소득 3.3% 원천징수**(계속·반복 활동 기준) + 소액부징수(세액 1,000원 미만 면제). 기타소득(8.8%·과세최저한) 계산기는 lib에 병행 구현해 정책 전환 대비 | P5의 '실사용 경로'가 곧 출금 흐름. 신청→운영팀 지급 처리(어드민 큐) |
| 4 | **예약형(라이트)** | 방문형의 옵션 `reservationRequired` — 상세·체험권에 "방문 전 예약 필수" 배지+안내. 별도 선정 절차는 도입하지 않음(즉시 발급 원칙 유지) | flags.ts 기존 주석("예약형은 추후 확장")의 1단계 구현 |
| 5 | **배송지 정보의 목적 제한 노출** | 배송형에 한해 수령인 이름·연락처·주소를 사장님 발송 화면에 노출(발송 목적 한정). **등급은 계속 비노출** | 확정 정책 8(익명 원칙)의 명시적 예외 — 데이터정책서에 근거 기록 |

### 2.2 보류 (운영정책서 §13 제안으로만 기록)

| 항목 | 보류 사유 |
|---|---|
| **구매평(페이백)·쇼핑 연동** | 선구매 유도 + 대가성 구매평은 가구매·리뷰 조작으로 흐르기 쉬움 — P4(실제 이벤트만) 정신과 충돌 위험, 표시광고법·플랫폼 약관(스마트스토어 등) 리스크 검토 선행 필요 |

| **유튜브·클립(숏폼) 채널** | 연동 채널 3종(블로그/인스타/틱톡) 확정 정책. 유튜브 API 연동 비용 대비 MVP 효용 낮음 |

| **주의 누적 페널티 체계(주의 5회→블랙)** | 우리는 월간 재평가 감점 모델로 이미 흡수. 출금 제한 연동(블랙 시 출금 불가)만 포인트 정책에 선반영 여지 |
| **포인트 유효기간·소멸** | 상법상 소멸시효(5년) 기준 제안 — 미확정 |

### 2.3 이미 우위인 항목 (참고)

- **SNS 연동 검증**: 레뷰는 미디어 URL 연결 중심 — 우리는 OAuth 본인 검증(네이버/Meta/틱톡 로그인)까지 구현.
- **등급 정책**: 레뷰의 선정 경쟁(신청→선정) 대신 즉시 발급 + 등급별 혜택 차등(P1) — 참여 진입장벽 없음.
- **대가성 표기**: 리뷰 제출 시 `adNoticeConfirmed` 서버 필수 검증 — 레뷰와 동등.

## 3. 반영 설계 요약

### 3.1 포인트 정책 (정본: 운영정책서 §14)

- 적립: 배송형 리뷰 검수 승인 시 `pointReward × SUPPORT_MULTIPLIER[참여 채널 등급]`, 100P 단위 반올림.
- 출금: 최소 10,000P · 1,000P 단위 · 이체 수수료 500P · 원천징수(사업소득 3.3%, 세액 1,000원 미만 소액부징수).
  실지급액 = 신청 포인트 − 원천징수세액 − 수수료. 신청 즉시 포인트 차감, 반려 시 전액 복구.
- 원장: `PointTxn` append-only — 파생 잔액은 합산 계산 (조작 방지·감사 추적).
- 프로토타입 한계: 주민등록번호는 수집하지 않는다(실서비스 전 수집 절차 필요 — 데이터정책서 §1.0b).

### 3.2 배송형 라이프사이클

```
신청(배송지 입력) → active("발송 대기", 기한=캠페인 종료일)
  → 사장님 발송 처리(운송장 입력, usedAt 세팅) → used("리뷰 작성", 7일 기한 — 기존 스윕 재사용)
  → review_submitted → completed(검수 승인 → 포인트 적립) | rejected(재제출 1회)
```

- 발급 후 72h 룰은 방문형 전용 — 배송형 active 기한은 캠페인 종료일 (기자단과 동일 패턴).
- 취소: 발송 처리 전(active)만 가능 — 발송 후 취소 불가.
- P2(방문형 지원금 = 매장 직접 할인·회사 무정산)는 방문형 전용으로 유지. 배송형 보상(제품+포인트)의
  정산 주체는 회사(포인트) — 사장님 캠페인 비용 청구 모델은 §13 미확정 제안.
