## 1. 검수 운영 (책임 분리)

- **사장님은 후기 조회만** 가능. 직접 검수·반려·통과 권한 없음 — `/api/passes/approve`는 **410 Gone**.
- 광고 표시 누락·재작성·부적절 콘텐츠 발견 시 → 사장님은 **[💬 채널톡으로 문의하기]** 로만 운영팀에 접수(ChannelIO, 미로드 시 `help@catchrank.co.kr` mailto 폴백).
- **운영팀 검수 콘솔(`/admin/reviews`)** 이 `review_submitted` 후기를 일괄 검수:
  - **통과**: `completed` + `reviewer.completedReviews++` + **체험자·사장님 양측 알림**.
  - **반려**: 사유(≤500자, 미입력 시 "작성 조건 미충족") → `rejectReason`·`rejectedAt` 구조화 보존 + 양측 알림. 사유는 **체험자 화면에 원문 그대로** 노출(재작성 근거).
- 자동 검수(시스템)는 미구현 — 체험자 **자가 점검**(채널별 항목) + 운영팀 전수/표본 검수.

### 1.1 반려·재제출 운영
- 체험자는 **반려 후 7일 내 1회** 수정·재제출(`resubmitCount<1` & `rejectedAt+7d` 이내). 기자단은 **캠페인 종료 전** 1회.
- 재제출 시 다시 `review_submitted` → 검수 대기열에 "후기 재제출"로 재등장(사장님 알림).
- **2회째 반려는 종착** — 이의는 고객센터(`help@catchrank.co.kr`) 경로만.

## 2. 체험권 라이프사이클 운영 (노쇼·만료·취소)

라이프사이클 스윕(`src/lib/pass-lifecycle.ts`)이 DB 로드마다 아래를 **멱등** 강제(별도 크론 없음):

> **2026-07-07 회의 확정 수치**: 체험권 유효기간 **발급 후 72시간**(개별 연장·복구 불가 — 예외적 코드 부활 없음, 정책상 불가로 처리) ·
> 리뷰 제출 기한 **이용(사용 처리) 후 7일** · 사용 전(active) 체험권 동시 보유 **최대 5장** ·
> 취소 후 동일 캠페인 재신청 **12시간 제한**(장기 점유 후 취소·재발급 악용 방지).

| 이벤트 | 조건 | 처리 |
|---|---|---|
| **만료 확정** | 방문형 active 72h 경과 | `expired` + `consumedSlot` 모집 슬롯 복구 + 체험자 `noShowCount+1` + **양측 알림**. **연장·복구 불가** |
| **리뷰 기한(7일) 초과** | used 상태 `usedAt+7d` 경과 | `noShowCount+1` + 양측 알림(1회, `overdueHandled`). 상태는 used 유지 — 목록·상세는 파생 표시 상태 **"제출 기한 초과"**(CTA 제거, 서버도 기한 경과 제출 차단) |
| **리뷰 마감 임박 리마인드** | used + 제출 기한 24시간 이내 | 체험자 알림 1회(`reviewDueSoonNotified`) — 기한 경과 시 제출 불가·감점 반영 고지 (2026-07-10) |
| **만료 임박 리마인드** | active 잔여 6시간 이내 | 체험자 알림 1회(`expiringSoonNotified`) — "방문이 어려우면 취소해 주세요" |
| **참여 취소** | 체험자가 active에서 직접 취소 | `POST /api/passes/cancel` → `cancelled` + 슬롯 즉시 복구 + 사장님 알림. **노쇼 미집계** |
| **발급 제한** | 발급 시점 검증 | ① active 5장 보유 시 400 ② 동일 캠페인 취소 후 12h 이내 400 ③ 종료 캠페인 400 ④ 기자단(MVP 제외) 403 |
| **사용 코드 오입력 잠금** | 4자리 코드 연속 5회 실패 | 해당 체험권 **10분 잠금**(`useCodeLockUntil`, 정답 입력도 차단·에러에 잔여 시도 안내). 브루트포스 방지. **인증 실패로 체험권 상태는 변경되지 않음**(만료 전이만 예외) (2026-07-10) |

- 취소/만료 후 같은 캠페인 **재참여 가능**하되, **취소 후 12시간 재신청 제한**이 적용된다(만료는 제한 없음 — 중복 가드는 active/used/review_submitted만 차단).
- 노쇼 방치보다 **취소를 유도**하는 정책(슬롯 회수로 다른 체험자에게 기회 환원). 단, 취소-재발급 반복 점유는 12h 쿨다운으로 차단.

### 2.1 캠페인 노출·종료 (발급 소진 ≠ 종료 — 2026-07-07 회의)

- **발급 소진과 실제 체험 완료를 구분**한다 (`src/lib/campaign-visibility.ts`).
  - `open`: 기간 내 + 잔여 발급분 있음 → 정상 노출·발급 가능.
  - `issued_out`: 발급분은 소진됐지만 **살아있는(active) 체험권**이 남아 있음 → 목록에 계속 노출(발급 마감 표시). 만료·취소로 슬롯 복구 시 자동 `open` 복귀.
  - `closed`: 기간 종료, 또는 발급 소진 + 살아있는 체험권 0 → 종료·비노출.
- 대기(웨이팅) 기능은 MVP에 포함하지 않는다(추후 검토).
- 관심 목록에 저장된 캠페인은 `closed`여도 목록에서 **유지**하고 "마감된 체험"으로 표기한다(상세 진입 가능·신청 불가).

### 2.2 MVP 서비스 범위 (2026-07-07 회의)

- 1차 출시는 **즉시 발급·자율 방문형 체험단만** 제공한다. **기자단은 MVP 제외**(`src/lib/flags.ts PRESS_ENABLED=false` — 탐색 세그먼트·신규 신청·발급 API 차단, 기존 발급 건의 작성·검수는 마무리 허용).
- 예약이 필요한 체험단(숙박·미용 등)과 예약 선정 기능은 **추후 버전에서 별도 확장**한다.

## 3. 멤버십 운영

| 플랜 | 가격(월) | 월 모집 한도 |
|---|---|---|
| Free | ₩0 | 5팀 |
| Basic | ₩13,900 | 15팀 |
| Standard | ₩25,900 | 50팀 |
| Premium | ₩38,900 | 무제한 |

- **"팀 수" = 캠페인 개수가 아니라 실제 체험자를 부를 수 있는 인원 수** (확정 정책 4) — 5팀은 1명 캠페인 5개로도, 5명 캠페인 1개로도 쓸 수 있고, 잔여 한도 내에서만 모집 가능(예: 50팀 중 40팀 사용 시 마지막 캠페인은 최대 10팀).
- 모든 플랜이 전 등급 모집 가능. **플랜 간 차이는 ①월 모집 팀 수 ②탐색 '추천순' 노출 우대** — 등급 우선 모집(부스팅)은 1차 모델에 도입하지 않는다(확정 정책 8-3, 기존 "A/S 우선" 정책·표기 폐기). 신규 가입 기본 **Free**.
- **추천순 노출 우대 (2026-07-10)**: 체험자 탐색·홈 리스트의 기본 정렬 '추천순' = ①신청 가능 여부(체험권 일시 소진 `issued_out`은 최후순위) ②**사장님 플랜 랭크(Premium > Standard > Basic > Free, 조회 시점의 현재 플랜)** ③캠페인 생성일 최신순. 종료 캠페인은 비노출(§2.1). **[P1] 이는 사장님 멤버십 기준의 마케팅 노출 우대이며 리뷰어 등급과 무관 — 체험자의 참여 자격·지원금에는 영향 없음.** 동일 사장님 연속 노출 제한은 미도입(§13).
- 사장님은 **총 모집 인원만** 입력 → `distributeQuota`가 전 플랜 균등 자동 분배(수동 등급 설정 없음).
- **[P1] 등급별 quota 버킷은 체험자 참여 자격이 아니다** — 배분·집계용 기록일 뿐이며, 체험자는 등급과 무관하게
  총 잔여 슬롯이 있는 한 참여할 수 있다(자기 등급 버킷 우선 차감, 소진 시 잔여 버킷 사용, N등급은 C 버킷부터).
  등급 차이는 체험자가 받는 **지원금 배율(S100/A80/B60/C40/N10%)**로만 나타난다.
- 월 한도 검증: 현재 캘린더 월 생성 캠페인 quota 합 + 신규 ≤ 한도. **quota_bonus 보상**은 한도에 가산되고 초과분만큼 만료 임박순 소진.
- **수기 청구 SOP(PG 연동 전)**: 멤버십 상향은 즉시 정책 적용 + 운영팀 수기 청구. **미납 시 Free로 조정 가능**(카피 명시). PG 연동 시 결제 완료 후 plan 반영 + `membership_discount` 소진으로 전환(연동 지점 PRD BM §PG).

## 4. 정산·비용 부담 (분쟁 방지 핵심)

```
사장님 ──(멤버십 구독료)──▶ 회사
사장님 ──(지원금 = 매장 즉시 할인)──▶ 체험자   ← 회사 미경유. 별도 정산·환급 없음.
회사   ──(기자단 정산금, 3.3% 원천징수, D+7)──▶ 체험자   ← 재원 = 사장님 종량제 선결제
회사   ──(바이럴 보상: 멤버십 할인·quota 보너스)──▶ 회원   ← 마케팅 비용
```

- **방문형 지원금 = 매장이 결제 시 직접 할인.** 회사 무정산. 사장님 폼·체험자 카드·약관(제11조) 3중 명시.
- **기자단 정산**: 검수 통과 후 **D+7 송금, 3.3% 원천징수**(소득세법). 재원은 사장님 종량제 선결제.
- 지원금 부스트(+N%)는 캠페인 **기준 지원금(S100%)을 상한**으로 가산 → 매장 초과 부담 없음.

## 5. 광고 표시(경제적 대가) 준수 관리 (표시광고법)

- 채널별 표준 문구를 작성 화면에 제공 + [복사] + "본 문구를 게시물에 포함했습니다" 체크.
- **`adNotice`는 서버 필수 검증** → `pass.adNoticeConfirmed` 보존(분쟁 근거). 누락 시 제출 400.
- **게시 유지 기간 (2026-07-10 확정)**: 전 채널 **등록일로부터 90일** 통일(기존 인스타·틱톡 30일 → 90일 상향). 제출 시점에는 유지 여부를 확인할 수 없으므로 자가 점검 항목이 아닌 **별도 필수 동의**("제출한 리뷰를 등록일로부터 90일 이상 유지하는 데 동의합니다")로 받고 서버가 검증·보존한다(`pass.keepAgreed`). 유지 기간 내 삭제·비공개 적발 시 처리 기준은 §13 제안 참조.

## 6. 바이럴(레퍼럴) 운영 — 재원·어뷰징

### 6.1 보상 매트릭스 (양면)
| 매트릭스 | 발신→수신 | 추천자 행운 박스 | 피추천자 환영 박스 |
|---|---|---|---|
| RR | 체험자→체험자 | 지원금 부스트(basic+10/silver+20/gold+30%) | 첫 체험 지원금 +50% 부스트 |
| RO | 체험자→사장님 | 지원금 부스트(동일) | 첫 달 멤버십 50% 할인 |
| OR | 사장님→체험자 | quota_bonus +3팀 | 첫 체험 지원금 +50% 부스트 |
| OO | 사장님→사장님 | membership_discount ₩10,000(다음 결제) | 첫 달 멤버십 50% 할인 |

- 박스 등급(발신자 누적 accepted): 0~2 일반(+10%) / 3~4 실버(+20%) / 5+ 골드(+30%).

### 6.2 보상 재원 원칙 (BM 정합)
- **지원금 부스트**는 캠페인 기준 지원금(S100%) 상한 내 가산 → **매장 예산 초과 부담 없음**.
- **멤버십 할인·quota 보너스**는 **회사 마케팅 비용**.
- 발행 보상은 전부 **실사용 경로 구현**: 부스트=사용 처리 시 자동 가산(`boostRewardId` 소진), quota_bonus=캠페인 생성 시 소진, membership_discount=결제 시 소진(PG 지점).

### 6.3 어뷰징 가드
- 토큰 1회용(`consumedBy`) · TTL 14일 만료 차단 · 셀프 추천 차단(`referrerId===refereeId` 400) · 매트릭스 일관성 검증.
- 부정 취득 보상 회수·이용 제한은 **약관 제12조** 근거 확보. 향후: IP/디바이스 단위 24h 가입 제한(로드맵).

### 6.4 사회적 증거 진실성
- 라이브 카운터·보상 수치 전부 **실데이터**(조작 noise 폐기). 폴링 10초. 빈 상태는 정직 카피("오늘 첫 박스의 주인공, 아직 없음"). (표시광고법 허위·과장 방지)

## 10. 등급 월간 재평가 (2026-07-08 설계)

체험자 등급은 **최초 연동 시 캐치랭크 지수 평가 모델 v1**(채널 영향력 밴드 정규화 — `src/lib/grade.ts indexScoreV1`, 실모델 API 도입 시 이 함수만 교체)의 지수 단독으로 산정하고, 이후 **매월 말(KST) 직전 1개월 활동을 재평가**한다 (오를 수도 내려갈 수도 있음). 실행은 크론 없이 DB 로드 시 lazy 스윕(`src/lib/grade-regrade.ts sweepMonthlyRegrade`), 소급 없음(직전 1개월만).

### 10.1 월간 등급 점수 (GS, 0~100, 채널별)

```
GS_ch = 0.70 × I_ch(지수점수) + 0.20 × F(성실 이행) + 0.10 × W(상생지수) − P(패널티)
```

| 요소 | 가중치 | 산출 |
|---|---|---|
| **I 지수점수** (채널별) | 70% | 지수 평가 모델 v1 — 가중 영향력(블로그 ×1.2)을 밴드 정규화: A[50k,500k)→70~89 · B[10k,50k)→50~69 · C[1k,10k)→30~49 · N→10~29 (밴드 내 로그 보간, 90~100은 S 예약 — v1 미산출) |
| **F 성실 이행** (공통) | 20% | 당월 완료율 = 완료 / (완료 + 노쇼 만료 + 리뷰 기한 초과 + 반려 종착) ×100 |
| **W 상생지수** (공통) | 10% | 완료 건별 초과 결제율 r = (결제액 − 적용 지원금) / 적용 지원금 → **min(r, 1.0)의 평균** ×100. 결제 기록이 있는 방문형 완료 건만 집계 |
| **P 패널티** (차감) | — | 노쇼 만료 **−10/건** · 리뷰 기한 초과 **−7/건** · 반려 종착(1회 재제출 후 추가 반려) **−5/건**. 월 차감 상한 **−30**, 직전 월에도 패널티가 있으면 **×1.5 누적 가중**. **취소는 무패널티**(§2 "노쇼 미집계" 유지 — 반복 점유는 12h 재신청 제한이 담당) |

> **리뷰 품질은 점수 요소로 평가하지 않는다** (검수자 주관 개입 배제 원칙). 품질 문제는 객관적 사건인 **반려 종착만** 패널티로 반영한다. `qualityScore` 필드는 미사용 확정(deprecated).

### 10.2 상생지수 모순 방지 4중 장치

"돈을 많이 쓴 체험자에게 높은 점수"를 주면 **등급 구매 → 지원금 배율 상승 → 할인 차익 회수**의 어뷰징 루프가 생기고, 저가 업종 체험자가 구조적으로 불리해지며, 등급의 본질(영향력·신뢰 신호)이 희석된다. 이를 막기 위해:

1. **비율 기반** — 자기 지원금 대비 상대값만 사용, 절대 금액은 어디에도 쓰지 않는다
2. **건별 상한 min(r, 1.0)** — 1회 고액 결제 몰아치기 무효
3. **완료 전제** — 검수 통과(completed) 건만 집계: 돈만 쓰고 리뷰를 이행하지 않으면 0
4. **가중치 상한 10%** — 상생만으로는 등급이 오르지 않는다

### 10.3 등급 매핑·안정 장치

- **등급 컷**: S≥90 · A≥70 · B≥50 · C≥30 · N<30. 지수 밴드가 컷과 일치하므로 활동 중립 시 지수 단독 산정과 동치.
- **S는 자동 부여 금지** — GS≥90 & 당월 노쇼 0 & 완료 5건↑이면 **S 후보**로 이력에 기록만 하고, 부여는 운영팀 수동(현행 "운영팀 부여" 원칙 유지). 이미 S인 체험자가 S컷을 유지하면 강등하지 않는다.
- **월 변동 폭 ±1등급** (급락·급등 방지).
- **표본 부족**(당월 이벤트 <2건): F/W 중립 처리 → `GS = I − P` (패널티는 항상 반영). **이벤트 0건**: 재평가 스킵 — 등급 유지, 이력만 기록.
- **평가월 중 가입자**: 해당 월 평가 대상에서 제외 (첫 재평가는 가입 다음 달 말).
- **월 귀속 기준**: 완료 = 검수 승인 시각(`completedAt`) · 노쇼 = 만료 시각 · 기한 초과 = 이용+7일 도래 시각 · 반려 종착 = 최종 반려 시각. 기한 초과 후 뒤늦게 완료된 건은 각 월에 각각 집계.
- 채널별 GS로 채널 등급 갱신, 종합 등급 = 연동 채널 중 최상위(현행 유지). 등급 변동 시 체험자 알림.

### 10.4 상생 리뷰어 뱃지

- **기준**: 월 재평가에서 **W ≥ 60 & 당월 완료 3건 이상** → 부여/갱신. **유예 1개월**(획득 후 미달 1개월은 유지), **2개월 연속 미달 시 회수**(알림 발송).
- **성격**: 인스타그램 인증 뱃지 같은 **표면적 신뢰 표식** — 지원금 배율·참여 조건에 일절 영향 없음([P1] 무관). 실제 상생 활동에서만 발생하므로 P4(실이벤트 기반 사회적 증거) 충족.
- **혜택 방향**: 향후 프로모션(쿠폰·이벤트 등) 발생 시 **우선 지급 대상**. VER.1은 뱃지 표시(등급 화면·MY)와 본 정책 명문화까지 — 프로모션 시스템 구현 시 이 조항을 지급 우선순위 규칙으로 사용한다.

### 10.5 P1 준수 확인

재평가·패널티·뱃지가 영향을 주는 곳은 **등급(=지원금 배율, 혜택 크기)과 표시**뿐이다. 참여 가드(`/api/passes` — 종료/채널 미연동/슬롯 소진/5장/12h)와 캠페인 노출(`campaign-visibility`)에는 어떤 조건도 추가하지 않는다. 재평가 산출물(GS·패널티·뱃지)을 참여/발급 분기에서 참조하는 코드가 등장하면 즉시 P1 위반으로 본다.

| 12 | 검색·리스트 페이지네이션 | 캠페인 규모(수십 건)에서는 미도입. 목록 200건 초과 시 무한 스크롤(커서 기반) 도입 제안 |
| 13 | 지역 기준점 좌표 정밀 검증 | 현행 REGION_CENTERS는 행정기관(도청/시청/구청) **인근 대표점** — 청사 이전·복수 청사 대응을 위한 좌표 관리 대장(연 1회 검수) 마련 제안. 반경 3km가 좁은 광역 지역(도 단위)은 "전체 보기" 유도 또는 반경 확대(5km) 옵션 후속 검토 |
| 14 | 추천순 연속 노출 제한 | 동일 사장님 다수 캠페인의 연속 노출 제한은 미도입(현행 매장 수 규모에서 불필요). 공급 확대 시 "동일 사장님 최대 2연속" 규칙 제안 |
| 15 | 지도 데이터 정비 | 좌표 없는 매장은 노출 제외 대신 **주소 지오코딩 폴백** 도입 제안(현행은 서울시청 폴백 좌표). 폐업·이전 매장은 사업자 인증 상태와 연동해 핀 비노출 처리 제안. 지역별 건수 집계는 **노출 캠페인(open+issued_out) 기준·매장(캠페인)별 집계** |
| 16-1 | SNS 검증 필수화 로드맵 | 현재 검증(OAuth)은 **신뢰 표식**이며 미검증(자기신고) 채널의 참여도 허용(현행 유지). 어뷰징(타인 채널 도용) 데이터가 쌓이면 **신규 연동은 검증 필수**로 전환 제안 — 기존 미검증 연동은 유예 기간 후 재검증 요구. 참여 게이트 전환 시에도 "채널 연동(+검증)" 조건이지 등급 조건이 아니므로 P1 무관 |
| 16-2 | 네이버 블로그 소유 확인 한계 | 네이버 프로필 API는 로그인 아이디를 반환하지 않아 블로그 주소 자동 검증 불가 — 현행 = 계정 본인 인증 + 입력 URL 귀속. 후속: **블로그에 1회용 인증 코드 게시 확인**(RSS/스크랩) 방식 제안 |
| 16-3 | 검증 재확인 주기 | 계정 양도·매매 대응 — 연 1회 재검증(재로그인) 요구 제안. 인스타 비즈니스 전환·틱톡 추가 scope 승인 시 팔로워 수 자동 동기화로 influence 자기신고 의존 축소 |
| 16 | 탐색 지역·필터 유지 범위 | 탐색 내 지역 변경은 **탐색 한정**(홈 미반영 — 현행 구현·URL 독립) 유지 제안. 필터는 URL 반영으로 새로고침·뒤로가기 유지, **앱 재진입(세션 간) 유지는 미도입**(홈 지역만 최근 선택 칩으로 보조) |
