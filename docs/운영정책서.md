> 관련: 데이터·개인정보 [`데이터정책서.md`](데이터정책서.md) · 화면 기능 [`기능정의서.md`](기능정의서.md) · 제품 요구 [`../PRD.md`](../PRD.md).

## 1. 검수 운영 (책임 분리)

- **사장님은 후기 조회만** 가능. 직접 검수·반려·통과 권한 없음 — `/api/passes/approve`는 **410 Gone**.
- 광고 표시 누락·재작성·부적절 콘텐츠 발견 시 → 사장님은 **[💬 채널톡으로 문의하기]** 로만 운영팀에 접수(ChannelIO, 미로드 시 `help@catchrank.co.kr` mailto 폴백).
- **운영팀 검수 콘솔(`/admin/reviews`)** 이 `review_submitted` 후기를 일괄 검수:
  - **통과**: `completed` + `reviewer.completedReviews++` + **체험자·사장님 양측 알림**.
  - **반려**: 사유(≤500자, 미입력 시 "작성 조건 미충족") → `rejectReason`·`rejectedAt` 구조화 보존 + 양측 알림. 사유는 **체험자 화면에 원문 그대로** 노출(재작성 근거).
- 자동 검수(시스템)는 미구현 — 체험자 **자가 점검**(채널별 항목) + 운영팀 전수/표본 검수.

### 1.1 반려·재제출 운영
- 체험자는 **반려 후 72시간 내 1회** 수정·재제출(`resubmitCount<1` & `rejectedAt+72h` 이내). 기자단은 **캠페인 종료 전** 1회.
- 재제출 시 다시 `review_submitted` → 검수 대기열에 "후기 재제출"로 재등장(사장님 알림).
- **2회째 반려는 종착** — 이의는 고객센터(`help@catchrank.co.kr`) 경로만.

## 2. 체험권 라이프사이클 운영 (노쇼·만료·취소)

라이프사이클 스윕(`src/lib/pass-lifecycle.ts`)이 DB 로드마다 아래를 **멱등** 강제(별도 크론 없음):

| 이벤트 | 조건 | 처리 |
|---|---|---|
| **만료 확정** | 방문형 active 24h 경과 | `expired` + `consumedSlot` 모집 슬롯 복구 + 체험자 `noShowCount+1` + **양측 알림** |
| **리뷰 72h 초과** | used 상태 `usedAt+72h` 경과 | `noShowCount+1` + 양측 알림(1회, `overdueHandled`) |
| **만료 임박 리마인드** | active 잔여 6시간 이내 | 체험자 알림 1회(`expiringSoonNotified`) — "방문이 어려우면 취소해 주세요" |
| **참여 취소** | 체험자가 active에서 직접 취소 | `POST /api/passes/cancel` → `cancelled` + 슬롯 즉시 복구 + 사장님 알림. **노쇼 미집계** |

- 취소/만료 후 같은 캠페인 **재참여 가능**(중복 가드는 active/used/review_submitted만 차단).
- 노쇼 방치보다 **취소를 유도**하는 정책(슬롯 회수로 다른 체험자에게 기회 환원).

## 3. 멤버십 운영

| 플랜 | 가격(월) | 우선 등급 | 월 모집 한도 |
|---|---|---|---|
| Free | ₩0 | 랜덤 | 5팀 |
| Basic | ₩13,900 | 랜덤 | 15팀 |
| Standard | ₩25,900 | A 우선(½) | 50팀 |
| Premium | ₩38,900 | S 우선(½) | 무제한 |

- 모든 플랜이 S~C 등급 모집 가능. 차이는 ① 우선 등급 ② 월 모집 팀 수. 신규 가입 기본 **Free**.
- 사장님은 **총 모집 인원만** 입력 → `distributeQuota`가 자동 분배(수동 등급 설정 없음).
- 월 한도 검증: 현재 캘린더 월 생성 캠페인 quota 합 + 신규 ≤ 한도. **quota_bonus 보상**은 한도에 가산되고 초과분만큼 만료 임박순 소진.
- **수기 청구 SOP(PG 연동 전)**: 멤버십 상향은 즉시 정책 적용 + 운영팀 수기 청구. **미납 시 Free로 조정 가능**(카피 명시). PG 연동 시 결제 완료 후 plan 반영 + `membership_discount` 소진으로 전환(연동 지점 PRD BM §PG).

## 4. 정산·비용 부담 (분쟁 방지 핵심)

```
사장님 ──(멤버십 구독료)──▶ 회사
사장님 ──(지원금 = 매장 즉시 할인)──▶ 체험자   ← 회사 미경유. 별도 정산·환급 없음.
회사   ──(기자단 정산금, 3.3% 원천징수, D+7)──▶ 체험자   ← 재원 = 사장님 종량제 선결제
회사   ──(바이럴 보상: 멤버십 할인·quota 보너스)──▶ 회원   ← 마케팅 비용
```

- **방문형 지원금 = 매장이 결제 시 직접 할인.** 회사 무정산. 사장님 폼·체험자 카드·약관(제11조) 3중 명시.
- **기자단 정산**: 검수 통과 후 **D+7 송금, 3.3% 원천징수**(소득세법). 재원은 사장님 종량제 선결제.
- 지원금 부스트(+N%)는 캠페인 **기준 지원금(S100%)을 상한**으로 가산 → 매장 초과 부담 없음.

## 6. 바이럴(레퍼럴) 운영 — 재원·어뷰징

### 6.1 보상 매트릭스 (양면)
| 매트릭스 | 발신→수신 | 추천자 행운 박스 | 피추천자 환영 박스 |
|---|---|---|---|
| RR | 체험자→체험자 | 지원금 부스트(basic+10/silver+20/gold+30%) | 첫 체험 지원금 +50% 부스트 |
| RO | 체험자→사장님 | 지원금 부스트(동일) | 첫 달 멤버십 50% 할인 |
| OR | 사장님→체험자 | quota_bonus +3팀 | 첫 체험 지원금 +50% 부스트 |
| OO | 사장님→사장님 | membership_discount ₩10,000(다음 결제) | 첫 달 멤버십 50% 할인 |

- 박스 등급(발신자 누적 accepted): 0~2 일반(+10%) / 3~4 실버(+20%) / 5+ 골드(+30%).

### 6.2 보상 재원 원칙 (BM 정합)
- **지원금 부스트**는 캠페인 기준 지원금(S100%) 상한 내 가산 → **매장 예산 초과 부담 없음**.
- **멤버십 할인·quota 보너스**는 **회사 마케팅 비용**.
- 발행 보상은 전부 **실사용 경로 구현**: 부스트=사용 처리 시 자동 가산(`boostRewardId` 소진), quota_bonus=캠페인 생성 시 소진, membership_discount=결제 시 소진(PG 지점).

### 6.3 어뷰징 가드
- 토큰 1회용(`consumedBy`) · TTL 14일 만료 차단 · 셀프 추천 차단(`referrerId===refereeId` 400) · 매트릭스 일관성 검증.
- 부정 취득 보상 회수·이용 제한은 **약관 제12조** 근거 확보. 향후: IP/디바이스 단위 24h 가입 제한(로드맵).

### 6.4 사회적 증거 진실성
- 라이브 카운터·보상 수치 전부 **실데이터**(조작 noise 폐기). 폴링 10초. 빈 상태는 정직 카피("오늘 첫 박스의 주인공, 아직 없음"). (표시광고법 허위·과장 방지)

## 9. 출시 운영·보안 체크리스트 (`.env.example` 참조)

| # | 항목 | 상태/조치 |
|---|---|---|
| 1 | **AUTH_SECRET**(32자+ 무작위) 설정 | 코드 하드닝 완료 — **미설정 시 production 부팅 거부(fail-closed)**, 개발용 폴백은 비-production 한정. 배포 전 env 설정 필수 |
| 2 | **Naver Map 키**: 재발급 + env 설정 | 코드 하드닝 완료 — 소스 **하드코딩 폴백 제거**, env(`NAVER_MAP_CLIENT_ID/SECRET`)로만 사용(미설정 시 지도 graceful 비활성). 저장소 이력에 노출된 **기존 키는 폐기·재발급 필요**(외부 콘솔 작업) |
| 3 | **Vercel KV 연결**(`KV_REST_API_URL/TOKEN`) | 미연결 시 서버리스 데이터 유실·인스턴스 불일치 → 운영 필수 |
| 4 | **ADMIN_REFRESH_TOKEN** 설정 | 미설정 시 production에서 `/api/admin/refresh-stores` 503(안전측) |
| 5 | SEED_VERSION 정책 | 운영 데이터 축적 후 bump = 전체 초기화. 운영 DB 전환 전까지 금지 |
| 6 | 채널톡 위젯 스크립트/라이선스 | 미연결 시 mailto 폴백 동작 |
| 7 | 운영팀 계정 비밀번호 변경 | `admin@catchrank.co.kr` |
| 8 | 법무 최종 검토 | `/legal/terms`·`/legal/privacy` 시행일 갱신 |
| 9 | 스토리보드 플래그 | 실 출시 시 `STORYBOARD=false` + 재시드 확인(데이터정책서 §4) |

> ⚠️ #1·#2의 **코드 측 하드닝(폴백 제거·env 강제·fail-closed)은 완료**됐다. 남은 것은 **운영/보안 조치**다 — AUTH_SECRET env 주입, 그리고 저장소 이력에 노출된 **Naver 키의 폐기·재발급**(Naver 콘솔 외부 작업, 본 작업 범위 외).
