## 0. 문서 사용 규칙 & 표기법

이 문서는 **IA(정보 구조)를 기반으로 각 화면에 반드시 들어가야 하는 기능 요구사항**을 정의한다.
**디자이너는 여기 정의된 기능·제약·디자인 의도의 범위 안에서만** 디자인하고,
**프론트엔드 개발자는 같은 표를 기준으로** 구현한다.

**기능내역(요구사항기능내역) 열 작성 규칙 — 아래 4요소를 반드시 포함:**
1. **위치·형태**: "ㅇㅇ 기능은 ㅇㅇ 화면 ㅇㅇ 위치에 ㅇㅇ처럼 들어간다."
2. **정량 제약**: 최대/최소 개수·자릿수·기간·시간(초)·금액 단위를 숫자로.
3. **디자인 의도**: 토스트 노출 시간, 고정 영역(bg fixed), 포커스·키보드 타입, 넘침 처리(캐러셀/스크롤), input 타입, 비활성 조건, 애니메이션 타이밍.
4. **데이터·연동**: 서버 호출 시 API 메서드·경로·필드·에러 코드.

**요구사항 ID 체계:** `CP_R_*` 체험자 · `CP_O_*` 사장님 · `CP_AD_*` 운영팀 · `CP_C_*` 공통.
요구사항(화면/기능영역) → 요구사항기능(개별 기능). 예 `CP_R_REQ4_4` = 매장 상세 화면의 4번째 기능(채널 선택 칩).

**개발가능여부:** ✅ 구현 완료 · 🔷 정책 확정·구현됨 · ⏳ 로드맵(미구현). 본 VER.1은 결제(PG) 외 전부 ✅/🔷.

**본 문서 문자열 규칙:** 큰따옴표(" ")로 감싼 문장은 **실제 UI 카피/서버 응답 원문**이다. 디자인·개발 시 **글자 그대로** 사용하며 임의 변경 금지(QA가 diff로 검증).

## 1. 용어 정의 (Glossary)

| 용어 | 정의 |
|---|---|
| 체험자(Reviewer) | SNS 채널을 연동하고 매장 체험 후 리뷰를 작성하는 회원. 진입 `/r/*`. |
| 사장님(Owner) | 매장을 등록·운영하고 캠페인을 개설하는 회원. 진입 `/o/*`. |
| 운영팀(Admin) | 리뷰 검수 전용 백오피스 계정. 진입 `/admin/*`. reviewer/owner 화면·보상 대상에서 제외. |
| 등급(Grade) | 채널 영향력 기반 5단계 **S / A / B / C / N**. 채널별로 독립 산정되며, 종합 등급 = 연동 채널 중 최상위. **[P1] 등급은 참여 자격이 아니다 — 모든 등급이 모든 캠페인에 참여하며, 등급은 지원금 배율(혜택 크기)만 결정한다.** |
| 채널(Channel) | 리뷰 게시 SNS. **네이버 블로그 / 인스타그램 / 틱톡 3종만**(유튜브 없음). 내부 키 `naver_blog`·`instagram`·`tiktok`. |
| 캠페인(Campaign) | 사장님이 개설하는 체험 모집 단위. 종류 = 방문형(visit) / 기자단(press). |
| 체험권(Pass) | 체험자가 캠페인에 참여해 발급받는 이용권. QR + (사장님용) 4자리 코드. 7-상태 라이프사이클. |
| 지원금(Support) | 체험권 사용 시 결제 금액에서 차감되는 **할인 금액**. **매장이 직접 제공**(회사 무정산). 기준 지원금 × 등급 배율. |
| 기준 지원금(supportAmount) | 사장님이 캠페인 생성 시 설정한 금액 = **S등급 100% 기준치(최대)**. |
| 등급 배율 | S 100% · A 80% · B 60% · C 40% · N 10%. 실지급 = 기준 지원금 × 배율(100원 반올림). |
| quota / used | 캠페인의 등급별 슬롯 배분(quota)과 발급 소진 수(used). **참여 자격이 아니라 배분 기록** — 발급 시 자기 등급 버킷 우선 차감(N은 C 버킷부터), 소진 시 잔여 버킷 사용. 총 잔여 0일 때만 "마감". 만료/취소 시 복구. |
| consumedSlot | 발급 시 실제 차감한 슬롯(자기 등급 버킷과 다를 수 있음). 만료·취소 시 이 슬롯을 복구하는 근거 필드. |
| 부스트(support_bonus_pct) | 초대 보상. 다음 체험권 **사용 처리 시** 지원금 한도에 +N% 가산(상한 = 기준 지원금 S100%). |
| 멤버십(Plan) | 사장님 구독 플랜 Free / Basic / Standard / Premium. 월 모집 한도로 차등. |
| 4자리 코드(useCode) | 캠페인별 사용처리 코드. **체험자 화면에 노출 안 함** — 사장님만 인지. |
| 자가점검(selfCheck) | 리뷰 작성 조건 충족을 체험자가 직접 체크. 채널별 항목 상이. |
| 광고 표기(adNotice) | 경제적 대가 고지 문구. 리뷰 제출 시 **서버 필수 검증**·보존(`adNoticeConfirmed`). |
| 익명 #last4 | 사장님·검수 화면에서 체험자는 id 끝 4자리만 노출(닉네임·이메일·SNS URL 비노출). |

## 3. 정보 구조(IA) & 네비게이션

**체험자 BottomNav (5탭, 고정 하단, 높이 72px):** 홈(`/r/home`) · 탐색(`/r/explore`) · 체험권(`/r/passes`) · 혜택(`/r/rewards`) · MY(`/r/me`).
등급(`/r/grade`)은 MY 하위 진입. 알림함(`/r/notifications`)은 전 화면 상단 종 아이콘.

**사장님 BottomNav (4탭):** 홈(`/o/home`) · QR 스캔(`/o/scan`) · 후기(`/o/reviews`) · MY(`/o/me`). 캠페인 생성·멤버십·로그·매장정보·리포트는 MY 허브 진입.

**운영팀:** BottomNav 없음(데스크톱 백오피스 톤). `/admin` → `/admin/reviews` redirect.

**전체 라우트 맵:**

## 4. 전역 UX 규약 (전 화면 공통 — 각 화면 표에서 재기술하지 않음)

| 상황 | 규칙 |
|---|---|
| **로딩** | 서버 호출 중 트리거 버튼은 비활성 + 라벨 "처리 중..."/"발급 중..."/"등록 중..." 등으로 전환. 리스트 로딩은 스켈레톤 없이 SSR(force-dynamic)로 초기 렌더. |
| **빈 상태(empty)** | 리스트가 0건이면 점선 테두리 카드 + 안내 문구 + 유도 CTA. 예: 체험권 "아직 발급된 방문형 체험권이 없어요." + [홈에서 체험권 받기 →]. |
| **에러(폼)** | input 하단 인라인 에러 텍스트(`text-error`, 14px). 서버 에러 문구는 §5 카탈로그 원문 사용. |
| **에러(치명)** | 데이터 조회 실패 시 안내 카드 + [다시 시도]/[홈으로]. 페이지 미존재는 `notFound()`(404). |
| **토스트** | 일시 안내는 화면 하단 토스트, **노출 3초** 후 자동 소멸(예: 코드 복사 "복사됨"). |
| **모달** | 확인/입력 모달은 하단 시트(dim `ink/45`, radius-top 18). 배경 탭 시 닫힘. 파괴적 동작(탈퇴·취소)은 **2단 확인**. |
| **키보드/Input 타입** | 이메일=email, 비밀번호=password, 금액·수치·4자리 코드=`inputMode="numeric"` + 숫자만 필터. 숫자 input은 포커스 시 넘버 키보드 활성화. |
| **넘침 처리** | 가로 목록(카테고리 칩 등)은 가로 스크롤. 칩 그룹은 `flex-wrap`. 긴 본문은 line-clamp. |
| **카운트다운** | 사용 기한/리뷰 마감은 1초 폴링 갱신(`Countdown`). 만료 시 "마감 지남" 표기. |
| **접근성** | 최소 탭 타겟 44px, 명도 대비 WCAG AA, 아이콘 버튼 `aria-label`, 상태색은 텍스트 라벨 병행(색맹 대응). |
| **금액 표기** | 천단위 콤마(`toLocaleString`) + **"원" 접미**(₩ 접두 금지 — 2026-07-07 표기 형식 규칙), 100원 단위. 큰 숫자 `tabular-nums`. |
| **표기 형식(스키마 마스크)** | 스토리보드 모드의 데이터 자리는 라벨명이 아닌 **형식 예시**로 노출: 금액 `000,000원` · 건수 `00건` · 수량 `00개` · 장수 `00장` · 인원 `00명` · 날짜 `0000.00.00` · 마감일 `00월 00일 까지` · 거리 `도보 00분` · 평점 `0.0`. 실데이터도 동일 형식(`src/lib/storyboard.ts` SBUI). |
| **반응형** | 모바일 뷰포트 폭 480px 기준. 초과 시 중앙 정렬 max-width 480. 운영팀만 데스크톱. |

## 6. 상태 머신 · 알림 매트릭스

### 6.1 체험권(Pass) 7-상태 전이

```
[발급] active ──(72h 미사용, 스윕)──▶ expired   (슬롯 복구 + noShow+1 + 양측 알림 · 연장/복구 불가)
       active ──(체험자 취소)──────────▶ cancelled (슬롯 복구, 노쇼 미집계, 동일 캠페인 12h 재신청 제한)
       active ──(사장님 사용 처리)──────▶ used
       used  ──(리뷰 제출, 이용 후 7일 내)─▶ review_submitted
       used  ──(7일 초과 미제출, 스윕)──▶ used 유지 + noShow+1 + 양측 알림(1회)
       review_submitted ──(운영팀 통과)─▶ completed (completedReviews+1)
       review_submitted ──(운영팀 반려)─▶ rejected  (사유 보존)
       rejected ──(반려 후 7일 내 1회 재제출)─▶ review_submitted (resubmitCount=1)
```
방문형 사용 기한 **발급 후 72h(연장·복구 불가)**, 리뷰 **이용 후 7일**. 기자단은 사용 기한=캠페인 종료, 재제출 기한=캠페인 종료.
발급 가드(2026-07-07): 종료 캠페인 M27 / active 동시 5장 M28 / 취소 후 12h M29 / 기자단(MVP 제외) M30.
노출: 발급 소진이어도 살아있는(active) 체험권이 남으면 캠페인 계속 노출(`campaign-visibility.ts` — open/issued_out/closed).
라이프사이클 스윕(`src/lib/pass-lifecycle.ts`)은 DB 로드마다 실행되며 만료 6시간 전 리마인드 알림도 발송.

### 7.3 비기능 요구사항 (Non-Functional)

- **인증/세션**: JWT(jose) HS256, httpOnly·secure 쿠키, 30일. AUTH_SECRET env 필수(미설정 시 production 경고).
- **비밀번호**: bcrypt 단방향 해시. 평문 저장 금지.
- **영속성**: 3단(메모리 → `/tmp` JSON → Vercel KV). 운영은 KV 필수. DB 로드마다 라이프사이클 스윕.
- **개인정보 노출 통제**: 사장님·검수 화면은 익명 #last4만. 닉네임·이메일·SNS URL 비노출.
- **관리자 도구**: `/api/admin/refresh-stores`는 production에서 ADMIN_REFRESH_TOKEN 미설정 시 503.
- **성능**: 리스트 SSR(force-dynamic). 카운터 폴링 10초. 지도/이미지는 지연 로드.
- **데이터 진실성**: 사용자 노출 수치(카운터·보상)는 **실제 발생 이벤트만** 집계(허위·조작 금지 — 표시광고법).
