# CATCHPASS · 스토리보드 스키마 프로토타입

> 디자인 파트가 "어떤 위치에 어떤 데이터가 들어가는지"를 한눈에 확인하고
> 레이아웃을 잡을 수 있도록, 목데이터·이미지를 **한글 스키마 라벨**로 치환한
> 프로토타입입니다.

## 브랜치 구조 (원복 안전장치)

| 브랜치 | 용도 | 데이터 |
|---|---|---|
| `claude/create-planning-prd-wdoZK` | 메인 개발 (실데이터 + 기능) | 실제 목데이터 / 사진 |
| `backup/real-mockdata` | **실데이터 보존용 백업** (원복 기준점) | 실제 목데이터 / 사진 (스토리보드 직전 시점 고정) |
| `design/storyboard-schema` | **본 스토리보드 프로토타입** | 한글 스키마 라벨 / "썸네일" placeholder |

### 원복 방법
- 실데이터 프로토타입으로 되돌리려면 `backup/real-mockdata` (또는 메인 개발 브랜치)로 체크아웃하면 됩니다.
- 또는 본 브랜치에서 코드 레벨로 끄려면 두 개의 플래그만 `false`로 바꾸면 실데이터 렌더로 즉시 복귀합니다.
  - `src/lib/storyboard.ts` → `export const STORYBOARD = false;`
  - `src/lib/store-photo.ts` → `const STORYBOARD = false;`
  - `src/lib/seed-runner.ts` → `const STORYBOARD = false;` (+ SEED_VERSION 되돌림)

## 치환 방식 (3계층)

1. **이미지** — `src/lib/store-photo.ts`
   - `photoForStore()`가 항상 `/store-photos/storyboard-thumb.svg`("썸네일" placeholder) 반환.
   - 모든 카드/히어로 썸네일이 동일한 "썸네일" 박스로 표시됨.

2. **문자열 데이터** — `src/lib/seed-runner.ts` (`SB` 사전)
   - 매장명→`매장명`, 카테고리→`카테고리`, 지역→`지역`, 캠페인명→`캠페인명`,
     기자단명→`기자단명`, 메뉴명→`메뉴명`, 설명→`캠페인설명`/`기자단설명`,
     닉네임→`닉네임`, 영업시간→`영업시간`, 주소→`주소`, 키워드/자료명 등.
   - DB 시드 단계에서 치환되므로 모든 화면에 자동 전파. `SEED_VERSION` 변경으로 자동 재시드.

3. **숫자·복합 표현** — `src/lib/storyboard.ts` (`SBUI` 사전)
   - 시드만으로 바꿀 수 없는 숫자/이미지/복합 표현을 화면 컴포넌트에서 라벨로 치환.
   - 지원금액→`지원금액`, 평점→`평점`, 리뷰수→`리뷰수`, 잔여→`잔여수량`,
     도보→`도보시간`, 등급→`등급`/`참여등급`, 마감일→`마감일`, 정산→`정산금액`,
     가격→`가격`, 모집인원→`모집인원`, 참여자수→`참여자수`, 평균지원금액 등.

## 스토리보드 적용 범위

체험자(디자인 주 대상) 전 화면 적용:
- `/r/home` — 큐레이팅 홈 (헤더, 동네 발견 배너, 3-카드, 가까운 곳/전체 리스트 2단 그리드)
- `/r/explore` — 탐색 (1단 축약 카드 / 2단 그리드 / 기자단 카드 / 3-stat)
- `/r/store/[id]` — 매장 상세 (히어로, 지원금액, 필수 메뉴+가격, 캠페인설명)
- `/r/grade` — 등급 (3-stat, 30일 성과, 등급별 혜택)
- `/r/rewards` — 혜택 (라이브 카운터, 박스 카드, 내 보상, 보낸 초대)
- `/r/passes` · `/r/passes/[id]` — 체험권 목록/상세 (지원금액/정산금액/가격)

> 사장님(`/o/*`) 화면은 시드 문자열 라벨(매장명/캠페인명/메뉴명)이 자동 적용되며,
> 숫자 필드(모집 인원/지원금 등)는 실값이 남아 있습니다. 디자인 스토리보드의 1차
> 대상은 체험자 발견 플로우이므로 우선 적용했습니다. 필요 시 동일 방식으로 확장 가능합니다.
