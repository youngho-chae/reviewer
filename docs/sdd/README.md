## 2. 왜 중단되었나 — Figma MCP 호출 한도

현재 인증 계정(`help@catchrank.co.kr`)이 **Starter 플랜 · View 시트 → Figma MCP 월 6회 호출 제한**.
남은 보드 생성에는 회당 1회 × 약 10회가 필요하다. 재개 방법 (택1):

1. **권장**: Figma **Professional 플랜 + Full 또는 Dev 시트** → 일 200회로 상향. 업그레이드 후 "이어서 실행해줘"라고 요청하면 아래 스크립트를 순서대로 실행한다.
2. Full/Dev 시트가 있는 다른 계정으로 Figma MCP 재인증 (파일 편집 권한 필요).
3. 다음 달 리셋 후 6회씩 나눠 실행 (비권장 — 10회 필요).

## 3. 스크립트 사용법

각 스크립트는 Figma MCP `use_figma` 도구에 **그대로 붙여넣어 1회 호출로 보드 1개**를 생성한다
(Claude Code 등 MCP 클라이언트에서 "이 파일 내용을 use_figma로 실행해줘" 하면 된다).

```bash
# 데이터 + 공용 생성기를 합쳐 실행용 파일 생성
cd docs/sdd/figma-scripts && ./build.sh   # → dist/board-R-00.js 등 7개 생성
```

실행 순서 (각 1회 호출):

| # | 파일 | 대상 페이지 | 만드는 것 |
|---|---|---|---|
| 1 | `01-guide-inventory.js` | 0:1 Guide | 가이드 섹션 5 — 화면 인벤토리 25행 + 작성 현황 |
| 2 | `dist/board-R-00.js` | 14:13 | R-00 가입·온보딩 (필수 동의) |
| 3 | `dist/board-R-03.js` | 14:13 | R-03 매장 상세 · 채널 선택 참여 |
| 4 | `dist/board-R-04a.js` | 14:13 | R-04a 체험권 상세 (7-상태 분기) |
| 5 | `dist/board-O-10.js` | 14:14 | O-10 캠페인 생성 |
| 6 | `dist/board-O-02.js` | 14:14 | O-02 사용 처리 (QR/4자리) |

2~4번, 5~7번은 서로 다른 x 좌표에 배치되므로 **병렬 호출 가능** (같은 메시지에 3개 tool call).

## 4. 보드 규격 (생성기가 강제하는 표준)

- **BOARD**: 1360px 고정 폭 · 흰 배경 · radius 24 · 세로 auto-layout · 프레임명 `BOARD · {화면ID}`
- **DocHeader**: 다크 바 — [화면ID 칩] 화면명 [라우트 칩] ←→ Device · Ver · 작성일 · 작성자 · [상태 칩]
- **좌측 목업(390px)**: 실제 앱 라이트 톤 와이어프레임. 정책이 걸린 요소마다 `AnnotationPin` 인스턴스(번호)
- **우측 Description**: 6열 (No./구분/명칭/기능 및 설명/예외·상태/이동·연관) — 핀 번호와 1:1
- **예외·유효성 표**: 상황 / 노출 문구(실제 카피 원문) / 처리(HTTP 코드)
- **상태 칩** + **데이터·연동**(API 메서드·경로·필드·lib 함수) + **변경이력**
- 폰트: Noto Sans KR(R/M/B) + Inter(Bold) — 파일에서 사용 가능 확인됨

## 5. 설계서 내용의 원본

각 보드에 들어가는 텍스트(정책·수치·카피·API)는 `figma-scripts/data/*.js`에 구조화되어 있다.
**이 데이터가 곧 화면설계서의 원문**이며, 전부 PRD.md v3.0 / 구현 코드에서 그대로 옮겼다
(카피 원문주의 — 서버 에러 문자열과 diff 가능).
Figma 없이 내용만 검토하려면 data 파일을 읽으면 된다.

## 6. 신규 화면 설계서 추가 방법

1. `figma-scripts/data/` 에서 기존 파일 하나를 복사해 DATA만 수정 (PRD §3의 ID·라우트 준수)
2. `./build.sh` → `dist/board-{ID}.js` 생성 → `use_figma`로 실행
3. Guide 페이지의 인벤토리 표에서 해당 행을 `✅`로 갱신
